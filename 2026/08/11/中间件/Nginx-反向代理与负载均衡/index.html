Nginx：从反向代理到负载均衡

一、为什么需要 Nginx（传统架构的瓶颈）

以前写完网站，直接用 IP + 端口 访问，单服务、用户少时”单兵作战”很完美。但用户一多就出问题：

  • 单台服务器被流量冲垮；
  • 加第二、第三台服务器做副本，但用户不知道该访问哪一台；
  • 某台服务器半夜死机，流量不该再往它发；
  • 网页静态图片和动态请求需要高效分流。

这时候就需要一个网络大管家——Nginx。

二、正向代理 vs 反向代理

记住一个词：保护谁。

  • 正向代理保护的是==客户端==：你主动通过代理访问外网，目标网站只知道代理 IP，不知道你的真实 IP（如公司上网行为管理）。
  • 反向代理保护的是==服务器==：用户访问 baidu.com，请求先打到 Nginx，再由 Nginx 悄悄转给后端；用户根本不知道、也不需要知道后端存在。

一句话：正向代理是”你带我去访问”，反向代理是”他来迎客”。 我们配 Nginx，就是让它当好这个”迎客的大管家”。

三、Nginx 的角色：餐厅前台（反向代理）

把后端服务器比作==餐厅厨房==，用户是==顾客==，Nginx 是==门口的服务员==：

  • 顾客把订单交给门口的 Nginx，Nginx 再送进厨房；
  • 厨房里有多个”厨师”（后端服务器），按类型精准送达；
  • 某个”厨师”突然不舒服（服务器宕机），Nginx 会完美避开他，顾客完全无感。

这种”在最前面统一调配资源”的模式，就是==反向代理==。

四、upstream：后端服务器组

要统一调配，Nginx 得知道后端有哪些服务。这组后端在 Nginx 里叫 upstream（上游服务器组）。

  • 在配置里写 upstream，把后端 IP、端口”排排站”，Nginx 就有了完整”花名册”；
  • 新请求进来，Nginx 从花名册里挑一台转发；
  • 后端 IP 变了，只改 upstream 一行，前端无感知。

五、负载均衡策略

Nginx 分发订单的核心策略（==面试高频==）：

策略 说明 适用场景
轮询 round robin 默认，按顺序一个一个，绝对公平 后端能力相近
权重 weight 能力强的给高权重，能者多劳 机器配置不均
ip_hash 按用户 IP 算哈希，同一用户永远分到同一台 解决登录 session 丢失
最少连接 least_conn 谁当前连接最少给谁，像聪明调度官 让每台都发挥最大价值

六、自愈与故障转移（健康检查）

默认情况下 Nginx 有极强的==自愈 / 容错==能力：

  • 转发请求到某服务器，发现超时或报错（如 502），不会把错误丢给用户，而是默默转给另一台；
  • 把故障服务器标记为”临时不可用”，一段时间内不再叫它；
  • 过一会儿发健康检查请求探活，好了再拉回来。

→ 自动隔离坏节点 + 自动尝试恢复，业务稳如泰山，半夜宕机也能安心睡。

七、动静分离

网页静态文件（图片 / CSS / JS）和后端 API 动态请求性质完全不同：

  • 后端处理动态计算强，但传静态文件慢；
  • Nginx 是 C 写的网络神器，读静态文件的并发能力恐怖。

→ 动静分离：Nginx 独自承包所有静态资源；遇到 API 动态请求再转后端。比喻：服务员顺手给饮料（静态），只有炒菜（动态）才进后厨。整体并发能力成倍提升。

八、核心配置文件解读（nginx.conf）

配置文件结构清晰，大括号层层嵌套。经典”反向代理 + 负载均衡”清单：

  • upstream 用 server 指令列出后端 IP、端口；
  • server 块代表 Nginx 监听的地址（如 80 端口）；
  • location 匹配访问路径；
  • 核心指令 proxy_pass 把请求转发给 upstream。

改完配置 nginx -s reload，新配置秒级生效、连接不中断。

九、常用运维命令

命令 作用
nginx -t 改完配置先别重启，用它检查语法；输出 syntax is ok 才安全
nginx -s reload 不关闭服务，热加载新配置
看 access.log 记录用户访问，排查流量
看 error.log 记录报错，应用报 502 就查它

十、核心速查表

  • 反向代理：挡在服务器前，统一迎客，保护后端、隐藏细节；承载后端团队，方便横向扩展。
  • 负载均衡：轮询 / 权重 / ip_hash / least_conn，让请求分流更合理。
  • 动静分离：Nginx 管静态，后端管动态，效率翻倍。
  • 健康检查：自动隔离故障、自动恢复，保证高可用。
  • 全部写在 nginx.conf，一行 nginx -s reload 生效。无论云原生还是传统架构，Nginx 都是==不可或缺的流量咽喉==。

十一、面试话术 / 深挖预演

正向 vs 反向代理
“正向代理保护客户端，用户主动借代理访问外网，目标站看不到真实 IP；反向代理保护服务器，用户请求先到 Nginx 再转发后端，用户无感知后端存在。区别一句话：保护谁。”

为什么用 Nginx 做网关
“Nginx 用 C 写、并发强，能做反向代理、负载均衡、动静分离、健康检查。多台后端靠 upstream 组织，proxy_pass 转发；某台挂了自动隔离+探活，业务高可用。”

负载均衡策略怎么选
“默认轮询；机器配置不均用 weight；要保 session 用 ip_hash（同 IP 固定后端）；想让每台都别闲着用 least_conn。”

动静分离的价值
“静态文件传输不是后端强项，Nginx 读静态并发恐怖。把图片/CSS/JS 交给 Nginx 直接返，只有 API 动态请求才进后端，整体并发成倍提升。”

配置改了怎么生效、怎么排错
“nginx -t 先验语法，再 nginx -s reload 热加载不中断连接；报 502 查 error.log，流量问题查 access.log。”
