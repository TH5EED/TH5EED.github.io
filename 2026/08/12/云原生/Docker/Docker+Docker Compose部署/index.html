Docker+Docker Compose部署

发表于2026-08-12|更新于2026-08-16|云原生
|浏览量:

一、定位：为什么 ci-01 装完整 Docker，K8s 节点却只装 containerd

K8s 三节点（.221-.223） ci-01（.231）
角色 部署终点，跑业务 Pod 构建端，CI/CD 平台宿主机
运行时 containerd 2.3.3 直装 完整 Docker（dockerd 内部仍是 containerd）
原因 只需”跑容器”，kubeadm 1.24+ 移除 dockershim，kubelet 走 CRI 直连 containerd 需要 Docker 的==工具链==：buildx/BuildKit 构建、Compose 编排、docker CLI 推 Harbor

面试话术（这条对比本身就是高频题）：

  • Docker 的内部分层：docker CLI → dockerd → containerd → runc。所以”Docker 底层就是 containerd”不是空话，K8s 只是把 dockerd 这一层跳过去了
  • 类比：containerd 是发动机，Docker 是整台车。K8s 节点只要发动机（kubelet 自己就是驾驶舱），ci-01 需要整台车（构建、编排、推送都是车上的功能）
  • 一句话总结：==同一套运行时，两种用法==——集群节点用裸 containerd 追求轻量直连，CI 机器用完整 Docker 换取工具链

ci-01 上随 Docker 安装的 containerd.io 包是 dockerd 的依赖，和集群三节点的 containerd ==完全独立、互不干扰==。

二、版本选择

组件 版本策略 说明
Docker CE / CLI 装当时最新稳定版 单机环境无跨节点一致性要求；dnf list docker-ce --showduplicates 可查历史版本
containerd.io 随 Docker 依赖自动带 不单独指定，保持与 docker-ce 配套版本
docker-buildx-plugin 最新 BuildKit 前端，流水线 Build 阶段（docker buildx build）用它
docker-compose-plugin 最新（Compose v2） 命令是 docker compose（==空格==）；老 docker-compose（连字符）是已停止维护的 python 独立版

装完把实际版本写到文末”装机状态”，与《新k8s部署全流程》一样留版本证据链。

三、安装步骤

前提：ci-01 的==虚拟机层工作已全部完成==——克隆开机四件套（hostname ci-01 / 静态 IP 192.168.31.231 / 能 ping 通 mirrors.aliyun.com）、系统盘扩容至 99G、80G 数据盘格式化挂 /data，过程与踩坑见《闭关虚拟机部署规划》Step 2 第 1、2 条。继承模板的已办事项：dnf 阿里云源、SELinux permissive、firewalld 关闭、无 swap、SSH 密钥。

第一步：添加 Docker 仓库（阿里云镜像源）

  • 与系统 dnf 阿里云源保持一致，国内速度快
  • 兜底：阿里云仓库异常时换官方源 https://download.docker.com/linux/centos/docker-ce.repo（K8s 三台装 containerd 用的就是官方源，实测可达）

第二步：安装 Docker + Compose 插件 + Buildx

  • 可选锁版本（追求可复现时）：dnf list docker-ce --showduplicates 查版本后 dnf install -y docker-ce-<版本> docker-ce-cli-<版本> containerd.io-<版本>
  • ==先别启动==：下一步写完 daemon.json 再 enable，避免先落系统盘再迁移

第三步：配置 daemon.json（先配置再启动）

参数逐条解释（面试点）：

  • data-root：镜像/容器/卷全部落到数据盘 /data/docker（默认是系统盘 /var/lib/docker）；数据盘已在虚拟机层挂好，见《闭关虚拟机部署规划》Step 2 第 2 条
  • registry-mirrors：docker pull 的加速源。达欧云 2026-08 实测可用，与 K8s 节点 containerd certs.d 同源；==注意它只对 docker pull 生效，BuildKit 构建时拉基础镜像不走这里==（见踩坑实录 3）
  • log-opts：容器日志滚动（单文件 100M × 3 份），防止某个疯狂打日志的容器写满磁盘——真实事故素材

第四步：启动与验证

==2026-08-12 收官实测==：Docker 29.7.2 默认启用 ==containerd image store==（docker info 见 driver-type=io.containerd.snapshotter.v1；docker images 输出变成 DISK USAGE / CONTENT SIZE 两列）。面试话术：Docker 把存储层也收敛到 containerd，BuildKit 与 docker pull ==共用同一个镜像库==——基础镜像用 docker pull（走加速源）预热后，构建时直接命中（呼应踩坑实录 3）。

第五步：Compose 冒烟测试（推荐做，一分钟换三个确认）

==实测==：curl 返回 200，down 清理完毕。hello-world / nginx:alpine 两个镜像留在数据盘作验证痕迹，无害，想清理 docker rmi 即可。

Compose v2 要点：

  • 命令是 docker compose（空格，CLI 插件形态）；docker-compose（连字符）是已 EOL 的 v1 独立版，教程里见到要知道是同一个东西的老写法
  • 文件名 compose.yaml / docker-compose.yaml 都认，新项目用前者
  • 与手写 docker run 的差别：==声明式==——一份 YAML 描述全部容器的镜像/端口/卷/依赖顺序，up -d 一键起、down 一键拆，可进 Git 版本化；后续 GitLab/Jenkins/Harbor 全用它编排

常用命令速查：

命令 作用
docker compose up -d 后台启动（缺镜像自动拉）
docker compose ps 看各容器状态
docker compose logs -f <服务> 跟踪单服务日志
docker compose exec <服务> bash 进容器
docker compose pull 只拉镜像不启动
docker compose down 停止并删除容器网络（卷默认保留）
docker compose config 校验并展开 YAML（排查语法）

四、为后续组件预留的约定（GitLab/Jenkins/Harbor 部署时的统一前提）

  • 数据目录全在 /data：/data/docker（daemon）+ /data/gitlab、/data/jenkins、/data/harbor、/data/runner（bind mount 进各 compose 服务）
  • 端口预分配与冲突预警：
组件 端口 备注
Jenkins 8080 Web UI
Harbor 80 / 443 镜像仓库
GitLab Web ==8090==（HTTPS 8443 或关） ==2026-08-12 定案==：GitLab 让路，Harbor 占 80/443；clone 地址带端口（http://192.168.31.231:8090），后续想要标准端口仍可前置反代
GitLab Git SSH 2222 22 被宿主机 sshd 占用，GitLab 配置里改 external SSH 端口
GitLab Runner 无监听 主动出站到 GitLab/Jenkins 与集群
  • firewalld 模板已关，端口直接监听无需放行；SELinux permissive，bind mount 无需 :z 后缀——==若日后切 enforcing==，所有 bind mount 要加 :z
  • Prometheus TSDB 按《闭关虚拟机部署规划》限死 retention（2d / 2GB），它是全链路唯一可能暴涨的磁盘消耗

五、踩坑实录（2026-08-12 收官：==全程顺利，未遇新坑==；以下预判保留作预防）

虚拟机/磁盘层的坑（加盘识别、fstab emergency、growpart）已归位《闭关虚拟机部署规划》Step 2 第 2 条，此处只留 Docker 本身的。

  1. daemon.json 语法错 → dockerd 起不来：改完先 python3 -m json.tool 校验；出错时 systemctl status docker / journalctl -u docker 能看到 “unable to configure the Docker daemon with file …”
  2. data-root 顺序问题：必须==先配置 daemon.json 再首次启动 docker==（数据盘 /data 已在虚拟机层挂好）。若已用默认目录跑过再想搬：systemctl stop docker → mv /var/lib/docker /data/docker → 写 data-root → 启动。用 mv 不用 cp（保留硬链接与权限）
  3. BuildKit 不走 registry-mirrors：docker buildx build 拉基础镜像是 BuildKit 独立拉取，绕开了 daemon 的 mirrors。对策：基础镜像先用 docker pull（走加速）预热到本地，BuildKit 命中本地即不远程拉；真要构建时也加速，需单独配 buildkitd 镜像（到 Jenkins 部署笔记再展开）

装机状态（2026-08-12 全部收官 ==done==）

  • 虚拟机层结果（磁盘扩容/挂载/VMID 105）记录在《闭关虚拟机部署规划》Step 2 第 2 条
  • Docker：==29.7.2==（默认 containerd image store）；Compose：==v5.4.0==（v2 形态插件）；Buildx 随 docker-ce 配套
  • 镜像库路径：/data/docker（Docker Root Dir 验证）；加速源 daocloud 实测秒级拉取
  • 冒烟：hello-world + compose nginx:alpine（curl 200）双通过；验证镜像保留

下一步：《闭关虚拟机部署规划》Step 2.4 部署 GitLab（代码仓库 + Webhook）。
