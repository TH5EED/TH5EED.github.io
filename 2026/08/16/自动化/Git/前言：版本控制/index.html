本地版本控制

工作原理

代表：RCS (Revision Control System)

  • 软件记录不同版本
  • 通过拍快照保存变更

例如：实验一最终版，实验一最终版2.0，实验一最终版2.1，实验一最终最终版…

优点

  • 操作简单
  • 不用网络连接
  • 适合个人使用

缺点

  • 不支持多人协作开发
  • 单机运行，存在单点故障风险

集中版本控制

工作原理

代表：SVN (Subversion)

  • 基于客户端/服务器架构
  • 服务器保存文件的所有更新记录和完整历史
  • 客户端只保留最新的文件版本
  • 需要从中央服务器获取最新版本，修改后再推送回服务器

优点

  • 支持多人协作开发
  • 权限管理清晰，适合企业
  • 版本历史集中管理，便于审计

缺点

  • 不联网情况下，用户只能查看本地自己所同步的版本，无法切换版本；
  • 不联网情况下，无法切换分支工作
  • 对带宽要求高
  • 服务器压力大
  • 存在单点故障风险（可采用高可用架构）

分布式版本控制

工作原理

代表：Git

每个人拥有全部代码

优点

  • 可以离线工作（可提交（本地），切换分支，查看历史）
  • 没有单点故障，数据安全性高，每个开发者都有全部代码，不依赖中央服务器
  • 性能优越

缺点

  • 安全隐患高，毕竟每个用户都有公司全部代码
  • 对于二进制文件处理不如SVN
  • 不易学习
