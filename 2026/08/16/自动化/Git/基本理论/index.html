工作区域

工作区

平时存放代码的工作目录（除.git外）

暂存区Stage

临时存放改动，本质是一个数据结构，位于.git/index中，存储了即将提交的文件快照

本地仓库

.git/ 目录下的全部内容

作用：

  • 安全持久化所有版本
  • 支持分支、合并、回退等操作
  • 每次 git commit 都会创建新的 commit 对象（有一个40位的哈希值）并更新当前分支指针

HEAD

指向当前分支或特定commit的指针，告诉用户”目前在哪“

当指向特定commit时
出现于执行力git checkout <hash>，此hash来自于git log结果中出现的前几位哈希值
此时处于分离头指针状态
如果此时再commit，即悬空commit，容易丢失
因为HEAD中内容已不再是指向某个分支，所以无法再指向该分支下的新commit

HEAD始终指向当前分支的最新commit对象（通过/refs/heads/<branch>可以验证）

文件 内容 什么时候改变
.git/HEAD ref: refs/heads/main 切换分支时改变（指向不同的分支引用）
.git/refs/heads/main abc123def456... 提交时改变（指向新的 commit）

本地版本控制工作原理代表：RCS (Revision Control System) 软件记录不同版本 通过拍快照保存变更 例如：实验一最终版，实验一最终版2.0，实验一最终版2.1，实验一最终最终版… 优点 操作简单 不用网络连接 适合个人使用 缺点 不支持多人协作开发 单机运行，存在单点故障风险 集中版本控制工作原理代表：SVN (Subversion) 基于客户端/服务器架构 服务器保存文件的所有更新记录和完整历史 客户端只保留最新的文件版本 需要从中央服务器获取最新版本，修改后再推送回服务器 优点 支持多人协作开发 权限管理清晰，适合企业 版本历史集中管理，便于审计 缺点 不联网情况下，用户只能查看本地自己所同步的版本，无法切换版本； 不联网情况下，无法切换分支工作 对带宽要求高 服务器压力大 存在单点故障风险（可采用高可用架构） 分布式版本控制工作原理代表：Git 每个人拥有全部代码 优点 可以离线工作（可提交（本地），切换分支，查看历史） 没有单点故障，数据安全性高，每个开发者都有全部代码，不依赖中央服务器 性能优越 缺点 安全隐患高，毕竟...
