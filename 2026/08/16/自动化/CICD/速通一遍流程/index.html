速通一遍流程

发表于2026-08-16|更新于2026-08-16|自动化
|浏览量:

环境需求

一主两从k8s集群
Harbor镜像仓库
gitlab（核心）

共5台机器，最好有一个代码检测工具，naxus

不引入Jenkins，只是用gitlab也能完成CI（gitlab-ci.yml），但是不灵活，Jenkins开源免费

CI

持续集成
开发者频繁将代码提交到主分支，并自动完成

  • 代码拉取
  • 编译构建
  • 单元测试
  • 代码检查（CI最后一步，CD前一步，代码检查工具在此发力）
    目标：尽早发现问题

CD

持续交付/部署
将构建好的软件自动发布到环境中

  • 测试环境
  • 预发布环境
  • 生产环境
    目标：让软件（微服务）随时可发布/自动发布

自动化流程

  1. 开发者提交代码 git push
  2. 触发CI webhook
  3. 拉取代码
  4. 编译构建 build
  5. 单元测试 test
  6. （可能会有代码质量检查）
  7. 打包制品 artifact
  8. 推送制品仓库 Nexus（jar包）/Harbor（8和9之间会有脚本）
  9. 自动部署 Docker/kubernetes（helm工具发布或升级）
  10. 发布完成（灰度发布，金丝雀，蓝绿发布）

虽说提交代码后自动触发后续所有流程，但发布一般还是手动发布
除非是大型企业，有一个平台化，比如说接入OA，提交一个发布申请
成熟的公司，CICD是非常完善的
