precheck.sh完整讲解

发表于2026-08-16|更新于2026-08-16|自动化
|浏览量:

第 0 步：先认识”脚本”本身

知识点 1：Shebang（脚本头）

这是脚本的第一行，意思是”用 /bin/bash 这个程序来解释执行我后面的内容”。#! 叫 shebang。没有它，系统不知道用哪个 shell 来跑。

知识点 2：注释

# 开头到行尾都是注释，机器忽略，给人看的。脚本里大段的 # ==== 和说明文字都是注释。

第 1 步：变量（脚本的”容器”）

知识点 3：变量赋值与引用

  • 变量名=值（等号两边不能留空格，A = 1 是错的）。
  • 用 $变量名 或 ${变量名} 取它的值。脚本里大量用 ${LIB_DIR}/base.sh 这种拼路径。
  • ${} 比 $ 更安全，能加花括号避免歧义、还能做”字符串加工”（后面会讲）。

知识点 4：命令替换 $(...)

$(命令) 表示”先运行里面的命令，把它的输出结果当作字符串拿回来”。

这里套了两层，从里到外读：

  1. ${BASH_SOURCE[0]} → 当前脚本自己的路径（比如 /home/user/precheck.sh）。BASH_SOURCE 是个数组，[0] 取第一个。
  2. dirname "..." → 取出路径的”目录部分”，得到 /home/user。
  3. cd 那个目录 && pwd → 切进去再打印绝对路径（这样即使你用相对路径运行，也能得到稳定的绝对路径）。
  4. 最外层 $(...) 把最终结果存进 SCRIPT_DIR。

一句话：这行让脚本无论你在哪个目录运行，都”知道自己在哪”。

第 2 步：函数（把一堆命令打包复用）

知识点 5：函数定义与调用

  • 名字() { ... } 定义一个函数。
  • 调用时只用名字：show_help、parse_args "$@"。
  • 脚本把功能拆成 parse_args(解析参数)、load_libs(加载库)、print_header(打印头部)、run_checks(跑检查) 等函数，结构清晰。

知识点 6：Heredoc（<< 多行文本）

cat << 'EOF' 表示”把接下来的多行文字，直到遇到单独一行的 EOF 为止，全部作为内容输出”。cat 负责把文本打印出来（显示帮助）。
关键：EOF 加了单引号 'EOF' → 表示里面的 $、\ 等**不要当变量展开**，原样显示。如果去掉引号，里面的 $SCRIPT_VERSION 就会被换成真实值。

第 3 步：参数处理（脚本怎么读你输入的东西）

知识点 7：特殊变量

变量 含义
$1 $2 … 第 1、2… 个参数
$@ 全部参数（当成一个个独立项）
$# 参数个数
$$ 当前脚本自己的进程号（PID）

脚本里 main "$@" 就是把你输入的所有参数原样传给 main 函数。

知识点 8：while 循环 + case 解析参数

  • while [[ $# -gt 0 ]]：只要”还有参数没处理”（$# 大于 0）就继续循环。
  • case "$1" in ...：看第一个参数是啥，匹配分支。
    • 碰到 --apply：把 APPLY_MODE 设成 true，shift（把 $1 丢掉，参数左移一位）。
    • 碰到 --hosts：它后面还跟一个值（"a,b,c"），所以 HOST_LIST="$2" 取第二个参数，然后 shift 2 丢掉两个。
  • shift 就像”出队”：每处理一个/两个参数就往前挪，直到 $# 变 0，循环结束。

知识点 9：条件判断 [[ ... ]]

[[ ]] 是 bash 的判断语法（比老式 [ ] 更强大）。常用：

  • [[ $# -gt 0 ]]：-gt 是”大于”。
  • 字符串相等用 ==，如 [[ "$APPLY_MODE" == "true" ]]。
  • 文件判断：[[ -f "$path" ]] 表示”这个路径是个存在的普通文件”；[[ ! -f ]] 加 ! 表示”不存在”。

知识点 10：exit 退出码

exit 0 正常结束；exit 1 表示出错了（非零通常代表失败）。脚本里遇到”缺少库文件””未知参数”就 exit 1 终止。

第 4 步：把代码拆成”库文件”（四层架构）

知识点 11：source 引入其他脚本

  • source 文件 = 把那个文件在当前环境里执行一遍。这样 base.sh 里定义的 _section、_print_summary 等函数，和 get.sh 里的 get_os_type 等，就都能在主脚本里直接用了。
  • 这个脚本的”四层分离”：基础设施(base) / 取数据(get) / 判断(check) / 修复(fix)，靠 source 组合成完整功能。
  • 严格性：local 表示”这个变量只在函数内部有效”，不污染外面。

知识点 12：数组

  • (a b c) 定义一个数组；"${files[@]}" 把数组里每一项摊开（@ = 全部元素）。

知识点 13：关联数组（key→value 的字典）

  • 普通数组下标是数字；关联数组下标是字符串，像个”字典”。多节点模式用它来记住”哪个进程号对应哪台机器”。

知识点 14：重定向 > >&2 和标准流

程序有三个”流”：

  • 标准输出 stdout（正常信息，默认显示在屏幕）
  • 标准错误 stderr（错误信息，默认也显示，但语义不同）
  • 标准输入 stdin（喂给程序的数据）

>&2 表示”把这条信息送到 stderr（错误流）”。好处：别人可以把正常输出和错误输出分开处理（2>/dev/null 可单独丢弃错误）。

第 5 步：管道与文本处理

知识点 15：管道 |（把一个命令的输出喂给下一个）

  • hostname -I 可能输出 10.0.0.1 192.168.1.1（多个 IP 空格隔开）。
  • | awk '{print $1}'：用 awk 取”第一列”，即第一个 IP。
  • || echo "unknown"：如果前面整条失败（比如命令不存在），就输出 unknown。|| = “前面失败才执行后面”。

知识点 16：set -uo pipefail（脚本的”安全开关”）

  • -u：遇到未定义的变量就报错退出（防止拼错变量名静默出 bug）。
  • -o pipefail：管道中任意一环失败，整条管道就算失败。
  • 注意：这里没有 -e（出错即停）。所以脚本里很多地方要手动 exit 1 来终止。

第 6 步：字符串加工（bash 的”内置小技巧”）

脚本里好几处 ${...} 的高级用法，集中讲一下：

写法 作用 本脚本用例
${HOST_LIST//,/ } 把所有逗号 , 换成空格 hosts=(${HOST_LIST//,/ }) 把 "a,b,c" 变成 a b c，再塞进数组
${host//[^a-zA-Z0-9]/_} 把所有”非字母数字”换成下划线 生成安全的临时文件名：precheck_result_$$_${host//.../_}
${remote_info%%|*} 从右删到第一个 |（贪婪） 取 `pid
${rest#*|} 从左删到第一个 |（最短） 取中间的 host
${rest##*|} 从左删到最后一个 |（贪婪） 取最后的 file

记忆口诀：# 从左边砍、% 从右边砍；一个符号是最短匹配，两个符号是贪婪匹配。

第 7 步：多节点并发（脚本最复杂的部分）

知识点 17：后台执行 & 和 wait

  • 命令末尾加 & → 扔到后台跑，脚本不等待、立刻继续。
  • $! → 刚才那个后台进程的”身份证号”（PID）。
  • 多节点模式就是：同时 SSH 到所有机器（并发，省时间），把每台的输出存到各自的临时文件，记下 pid→host→file 的对应关系。
  • wait 进程号 → 等它结束。全部等完后，再 cat 各临时文件，把每台机器的检查结果打印出来。

知识点 18：SSH 远程执行本脚本

  • ssh 主机 命令：在远程机器上执行命令。
  • bash -s -- 参数：让远程机器用 bash 读标准输入里的脚本（-s 表示”从 stdin 读脚本”）。
  • < "$SCRIPT_DIR/precheck.sh"：把本机脚本内容”喂”给远程的 bash -s，等于把脚本传到远程并执行。
  • -o ConnectTimeout=10：10 秒连不上就放弃；StrictHostKeyChecking=no：跳过”首次连接确认”那一步（自动化场景常用）。

⚠️ 小提醒：第 8–9 行注释写的是 “QFusion v4.1.3”，但脚本内部 SCRIPT_VERSION="1.0.0"，而且 run_remote 用的是 --mode，而 parse_args 里并没有定义 --mode 这个参数——这几个地方和注释对不上，实际跑多节点时 --mode 会被当成”未知参数”报错。这是脚本现有的一处不一致，你可以留意一下。

第 8 步：把前面串起来看 main

[[ -n "$HOST_LIST" ]] 意思是”如果 HOST_LIST 变量不是空字符串”。你在命令行加了 --hosts，它就有值，走多节点；没加就是空的，走单节点。

给你的”阅读顺序”建议

作为 shell 小白，建议按这个顺序自己动手试：

  1. 先抄写并跑一段：变量 + echo + $(date) → 感受”命令替换”。
  2. 写一个带 --name 参数的小脚本，用 while/case/shift 解析 → 这是本脚本最难也最核心的部分。
  3. 写一个 source 另一个文件的例子 → 理解”库”的概念。
  4. 最后再看 run_multi_node 的 & + 关联数组 + SSH，那是进阶内容。
