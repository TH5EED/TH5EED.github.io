Precheck 项目学习路线图

目标：面试时能讲清楚架构、能复现某个检查项的完整链路、能回答追问

知识全景图

本项目涉及的知识点，按面试出现概率分为三级：

第一阶段：Shell 基础（1-2 天）

1.1 函数与变量作用域

对应代码位置: base.sh:29-46, check.sh:156-166

必须搞懂的概念:

检验标准: 能不看代码回答：

  • $(get_xxx()) 和直接调用 get_xxx() 有什么区别？
  • local 不写会怎样？（答案：会污染全局作用域）

1.2 字符串操作（项目用了大量模式匹配）

对应代码位置: check.sh:157-159, check.sh:344-347, get.sh:65-70

必须掌握的四种操作:

检验标准: 给你 "hello.world.txt"，能写出提取各部分的命令。

1.3 条件判断与 case

对应代码位置: check.sh:133-149 (SELinux), check.sh:186-206 (firewalld)

检验标准: 能解释为什么项目里用 [[ ]] 而不是 [ ]。

1.4 命令组合与退出码

对应代码位置: precheck.sh:20 (set -u), fix.sh:44-50 (幂等性)

检验标准: 能解释三个 bug 各自的根本原因。

第二阶段：理解架构（2-3 天）

2.1 四层架构——能画出来就能讲清楚

这是面试第一问，必须烂熟于心。

检验标准: 拿一张白纸，能画出这个图，并说出每层的输入和输出。

2.2 配置驱动机制

对应代码位置: check.sh:11-37 (config_get/config_enabled), precheck.conf

核心思想: 行为不硬编码在代码里，而是从外部配置读取。

三种 action 的区别:

action check 模式输出 apply 模式行为
check 不达标 → [FAIL] 不达标 → 尝试 fix
warn 不达标 → [WARN]（不阻断） 不达标 → 尝试 fix
fix 同 check 一定会尝试修
skip 整项不显示 整项不执行

检验标准: 能回答”客户要求忽略 IO 调度检查，你怎么做？”→ 改配置文件一行 enabled=false，不用改代码。

第三阶段：精通一个检查项（2-3 天）

选 check_io_scheduler 作为你的招牌检查项——它是最复杂的，覆盖了所有设计模式。

3.1 能从头到尾复现这个检查项的完整链路

面试时可能被要求：”挑一个你最满意的检查项，讲讲它的实现”

第一步：数据是怎么来的（get 层）

第二步：判断逻辑是怎么做的（check 层）

第三步：修复怎么做（fix 层）

检验标准: 面试时能在白板上写出以上三层代码的关键行，并解释每一行的作用。

第四阶段：Linux 系统知识（贯穿学习）

这些不是 shell 语法，而是这个脚本涉及的 Linux 概念。不需要深挖原理，但要能说出”是什么”和”为什么要检查”。

4.1 必须知道的系统文件/命令

检查项 涉及的文件或命令 它是什么 为什么要检查
操作系统 /etc/os-release 系统发行版信息 QFusion 只支持特定 OS
内核版本 uname -r 内核版本号 需要 4.19+，太老有兼容性问题
SELinux getenforce + /etc/selinux/config Linux 安全模块 强制访问控制会干扰数据库安装
Swap free + /etc/fstab 交换分区 K8s 要求关闭 swap，否则 pod 可能被 OOM Kill
firewalld systemctl status firewalld 防火墙服务 集群节点间通信不能被防火墙阻拦
NetworkManager systemctl status NetworkManager 网络管理服务 CentOS 7 上会和 network 冲突
主机名 hostname + hostnamectl 机器名称 K8s 用主机名标识节点，不能重复/不能有大写
IO 调度 /sys/block/sdX/queue/scheduler 磁盘 I/O 调度算法 影响 etcd 写延迟和数据库切换速度
k8s 依赖包 rpm -q RPM 包管理器查询 缺包会导致 K8s 安装失败
时区 timedatectl 系统时间配置 集群节点时间不一致会导致证书/认证问题

4.2 IO 调度算法（面试可能追问原理）

第五阶段：面试模拟（最后 1-2 天）

5.1 自测清单

  • 能在 30 秒内说出四层架构每层的职责和输入输出
  • 能画出一个检查项的完整调用链路图（推荐 IO 调度）
  • 能解释 ${var%%|*} 和 ${var##*|} 的区别
  • 能解释为什么不用 set -e
  • 能说明配置文件 enabled=false 和 action=warn 的区别
  • 能说出 fix 函数的”幂等性”是什么意思、怎么实现的
  • 能讲一个踩过的 bug 故事（set-e / 变量拼写 / $1 未绑定）

5.2 高频追问准备

Q: 如果要加一个新检查项（比如检查磁盘空间），你需要改哪些文件？

答：只需要改 3 个文件：

  1. get.sh 加一个 get_disk_usage() 返回使用率百分比
  2. check.sh 加一个 check_disk() 调 get → 判断阈值 → _ok/_fail
  3. precheck.conf 加一个 [disk] section
    base.sh / fix.sh / precheck.sh 完全不用动。这就是分层的好处。

Q: 多节点模式下，计数器会不会乱？

答：不会。SSH 远程执行时，每次连接是一个独立的 bash 进程，全局变量 _PASS_COUNT 等在各节点进程中独立存在。主节点通过后台进程收集各节点的输出文本，不做计数合并。如果要做汇总统计，需要在主节点解析各节点的输出。

Q: 这个脚本有什么可以改进的地方？

答：（说 1-2 个真实的就行）

  1. INI 解析器比较简陋，遇到复杂嵌套结构会出问题——但当前场景够用
  2. 可以加 --json 输出模式，方便 CI/CD 系统解析结果
  3. 版本比较函数目前用 sort -V，可以封装成更清晰的 version_lt()/version_gte()

学习顺序建议

总时间：约 10 天，每天 1-2 小时。核心是 Day 3-7 的架构理解和单项精通。
