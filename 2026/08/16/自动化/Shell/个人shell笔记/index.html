set -euxo pipefail 怎么”看执行过程”

这四个是一组防御+调试开关,常写在所有脚本开头:

开关 作用
-e 任意命令返回非 0(出错)就立刻退出脚本,防止错误被忽略后继续乱跑
-u 用到未定义的变量直接报错退出,避免拼错变量名变成空值悄悄出错
-x 把每条命令执行前先打印出来(变量已展开),这就是”看执行过程”的主角
-o pipefail 管道 cmd1 | cmd2 中只要任一环节失败,整条管道就算失败(默认只看最后一条)

==注意：shell中true的返回码是0==

看执行过程靠的是 -x:它会把脚本实际跑的命令(连变量替换后的样子)一行行打到终端,前面带 + 号。

用法有两种:

到 false 这一行(返回非 0),因为 -e 的存在脚本直接退出,最后那句 echo 永远不会跑。排查”脚本到底在哪一步、用了什么值”时,-x 是你最常用的一招。

小技巧:只想追踪某一段,可以局部开关:

假设某天 app.log 被改名或删了:

  • 没 pipefail:grep 找不到文件返回非 0,但 wc -l 拿到空输入返回 0 → 整条管道 = 0 → set -e 不拦 → count 变成 0 → 你以为”今天 0 个错误,一切安好”。其实你根本没读到日志,是假平安。
  • 有 pipefail:grep 失败 → 整条管道非 0 → set -e 直接终止,你马上发现”日志没读成功”,而不是被一个假的 0 骗过去。

这就是它存在的意义:别让管道前半段的失败,被后半段的成功悄悄掩盖。 配合 set -e,你的脚本才是真的”出错即停”。

命令使用

凡是路径、文件名、变量，一律套双引号，闭眼加，不用想。

使用命令要加$()

cd $(dir /root/thx/shell/hello.sh)
为避免路径有空格，加引号
cd "$(dir /root/thx/shell/hello.sh)"
