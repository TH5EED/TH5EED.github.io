内存结构

共享内存

所有线程共享区域
最重要的是共享缓存区shared_buffers：缓存了从磁盘读取的数据页，减少了慢速的磁盘IO

cstore_buffers是为列存表准备的独立缓存区，是处理列存数据的工作台

会话(本地)内存

每个工作线程私有，互不干扰

  • work_mem 用于排序，哈希连接等操作的内存
  • temp_buffers 访问数据库临时表
  • maintenance_work_mem 维护操作

物理结构

docker run -it –rm –name qfusion-ansible -e RESERVE_HOSTNAME=true -v $(pwd)/../:/qfusion/ registry.woqutech.com/woqutech/qfusion-ansible:2.9.27

  • 所有的数据、日志和配置最终都以文件的形式存放在磁盘上

  • 数据库集簇（Database Cluster）就是一个包含所有数据的顶层目录

  • 数据文件 (Data Files)：实际存储表、索引数据。一个表或索引可能由多个文件组成，除了主体（main），还有空闲空间映射（_fsm） 和**可见性映射（_vm）。

  • 日志文件 (Log Files)：

    • 预写日志 (WAL)：最关键，确保事务的持久性。

    • 运行日志：记录数据库运行状态和错误信息。

    • 审计日志：记录用户操作行为。

  • 控制文件 (Control File)：记录数据库的元数据，如当前WAL位置、检查点信息等，是启动和恢复的关键。

后台进程

不同于pg的多进程：实例中进程隔离性强，不至于一个进程崩溃导致整个实例崩溃

vb采用单进程，多线程，线程间通信效率高，资源开销小
启动实例后，会创建一个主进程，该进程内部会运行多个线程各司其职。

  • 主线程 (Postmaster)：整个实例的“大总管”**，第一个启动，负责初始化全局资源、监听端口、接收并分配客户端的连接请求。

  • 业务处理线程：Postmaster接收请求后，会分配一个业务处理线程来专职服务。它负责SQL的解析、优化、执行并返回结果。

  • 关键后台线程：它们在后台默默维护数据库，确保数据安全和高效。

    • BgWriter & PageWriter：“数据搬运工”，负责将共享缓冲区中修改过的“脏”数据页写入磁盘。

    • WalWriter：“日志记录员”，负责将预写日志（WAL）从内存缓冲区写入磁盘，保证事务持久性。

    • Checkpointer：“检查点专员”，定期将内存中所有修改同步到磁盘，并更新检查点，以加速故障恢复。

    • Stats Collector：“统计员”，收集表和索引的访问、大小等统计信息，供查询优化器和autovacuum使用。

    • AutoVacuum：“清洁工”，自动清理“僵尸”数据并更新统计信息。

服务与实例
vb_start/stop/restart（systemctl start mysql)是对于数据库服务的启动关闭管理 vsql连接实例（mysql -u也是这样），创建一个新的进程，此进程为实例 实例才是真正占用CPU，内存的进程，重启进程代表该进程死亡，也就是我们说的数据库挂了数据库服务是在系统中的一段配置 当从客户端登陆进去后，实例主进程会专门派一个子进程接待，退出后该进程被杀死 ==总结==数据库软件装好后，我们启动服务，操作系统就会在后台跑起一个实例（进程）。这个实例守着硬盘上的一堆数据文件。文件里划分了多个数据库（仓库），每个仓库里又分了多个模式（文件夹），文件夹里面才是我们天天打交道的表和列。
