TODO：常用网络模式

发表于2026-08-16|更新于2026-08-16|网络与安全
|浏览量:

桥接模式

普通NAT

介绍

VirtualBox默认网络模式
硬编码规定

  • 每个虚拟机IP：10.0.2.2
  • 网关（路由器）和DHCP：10.0.2.15
  • DNS：10.0.2.3

特点

  • 设备间无法通信
  • 虚拟机之间没有局域网连接
  • 每个虚拟设备有独立的NAT设备

虚拟机A：10.0.2.15 → 独立NAT设备：10.0.2.2 → 宿主机网络
虚拟机B ：10.0.2.15→ 独立NAT设备：10.0.2.2 → 宿主机网络
虚拟机C ：10.0.2.15→ 独立NAT设备：10.0.2.2 → 宿主机网络

NAT模式下虚拟机访问百度的完整流程

DNS解析（将”百度”转换为IP地址）

建立TCP连接（三次握手）

发送HTTP请求

接收HTTP响应

总结

NAT网络

  • 设备间可以通信
  • 虚拟机之间有局域网连接
  • 共享同一个NAT设备

虚拟机A ─┐
虚拟机B ─┼→ 共享NAT设备 → 外网
虚拟机C ─┘

IP分配

路由器从云厂商那里获取一个公网IP地址
路由器内部维护一个私有IP地址池，比如常见的192.168.1.x，10.0.0.x
通过路由器内置DHCP服务自动分配这些私有地址给到家里的多个网络设备
设备A：192.168.1.10，设备B：192.168.1.11，设备C：192.168.1.12
网关：192.168.1.1路由器本身

地址转换

路由器的NAT功能
当私有IP想要访问外网时，NAT将私有地址转为公有地址并记录端口

地址转换过程：

  1. 设备A向外网发起请求
  2. 路由器将192.168.1.10:随机端口转化为公网IP:特定端口
  3. 数据包到达目标地址
  4. 目标地址返回响应
  5. 通过端口映射转发给设备A
    不提到DNS原因：访问DNS也是上述一样的流程进行地址转换

TCP，UDP
TCP 是面向连接的，服务端必须显式调用 listen() 系统调用，内核才会把该 socket 标记为 LISTEN 状态，放入半连接队列等待 SYN。 UDP 没有连接概念，服务端调用 bind() 绑定端口后就可以直接 recvfrom() 收数据了。内核中没有 UDP LISTEN 这个状态。 TCP（电话） UDP（公告栏） 本质 面向连接，有状态机 无连接，无状态机 “监听”的含义 拿起听筒等铃响 → LISTEN 把公告栏钉在墙上 → UNCONN “已建立” 通话中 → ESTAB ❌ 不存在真正的”已建立” 内核状态数 10+ 种（SYN_SENT, TIME_WAIT…） 仅 2 种：UNCONN / ESTAB*
