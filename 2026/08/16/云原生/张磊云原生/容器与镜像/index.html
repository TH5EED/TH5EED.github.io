介绍

  • 容器技术的兴起源于 PaaS 技术的普及

  • Docker 公司发布的 Docker 项目具有里程碑式的意义

  • Docker 项目通过“容器镜像”，解决了应用打包这个根本性难题

程序与进程

程序是代码的二进制文件+需要用到的数据文件
当程序被执行起来，用到各种计算机执行环境（比如寄存器，内存堆栈等）的总和，就叫做==进程==

对于进程来说
静态表现就是程序
动态表现就是计算机的数据和状态的总和

容器三大实现技术

容器核心技术在于==约束和修改进程的动态表现==，为容器创造一个边界
主要技术为Cgroups制造约束，Namespace修改进程视图

namespace技术

  • Linux内核提供的一种资源隔离机制，它可以将全局的系统资源包装成多个独立的”副本“

  • 每个进程可以关联到一组命名空间，从而只能看到自己“所属”的那份资源

系统资源
PID，网络设备，挂载点，用户ID等

容器（如 Docker、containerd）正是通过为每个容器创建一套独立的命名空间（至少包括 pid、net、mnt、uts、ipc），从而实现进程隔离、网络隔离、文件系统隔离等

==容器在Linux内核视角来看，就是一个特殊隔离属性的进程==

命名空间类型 隔离的资源
mount 文件系统挂载点（容器拥有独立 /）
uts 主机名与域名（uname）
ipc System V 和 POSIX 消息队列、信号量
pid 进程 ID 编号空间（容器内 PID 从 1 开始）
net 网络设备、路由表、防火墙规则
user 用户与组 ID 映射（非特权容器）
cgroup cgroup 根目录视图（限制资源时可独立）
time 系统时间（较新内核）

/proc查看命名空间

/proc/[pid]/ns/ 目录下每个文件代表一种命名空间（符号链接）

Cgroups技术

多个容器之间虽然相互隔离，但并非绝对隔离

  • 共同使用宿主机的系统内核

  • Linux内核中有许多资源和对象不能被Namespace化，比如时间

==Cgroups技术用来为进程设置资源限制实现制造约束的效果==
