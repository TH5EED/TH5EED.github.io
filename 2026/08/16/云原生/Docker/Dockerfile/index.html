Dockerfile

是什么

Dockerfile 是一个构建镜像的文本脚本，由一条条指令组成，docker build 从上到下逐行执行，最终产出一个镜像。

先立两个心智模型（==镜像 = 文件系统 + 元数据==）：

类比 镜像世界 说明
装机 镜像 = 冻住的系统盘 + 启动配置 rootfs（分层文件系统）+ 元数据（启动命令/环境变量/端口/工作目录）
面向对象 镜像 = 类，容器 = 对象 docker题目已记，此处不重复
Git 一层 ≈ 一次 commit 每层记录一次文件系统变更，只增不改

构建流程与构建上下文

  1. 客户端把上下文目录整个打包成 tar 发给 Docker daemon（所以目录下别放无关大文件）
  2. daemon 逐行执行指令，==每条指令产出一个中间镜像，逐层提交==
  3. 构建完成，最终镜像打上 -t 指定的标签

配套 .dockerignore（语法同 .gitignore），把 node_modules、.git、日志等排除在上下文之外——减小传输体积 + 避免缓存被无关文件打断。

分层原理（核心）

三条铁律：

  1. ==只有改动文件系统的指令才产生真实的层==：RUN、COPY、ADD
  2. ENV/WORKDIR/EXPOSE/CMD/ENTRYPOINT 等==只写元数据，不产生层==（docker history 里显示为 0B 记录）
  3. ==所有镜像层都是只读的==；docker run 时在最上面叠加一层「容器可写层」，容器写入全部发生在这层，删容器即丢失（所以持久化要用 Volume）

底层实现：联合文件系统（UnionFS，Docker 默认 OverlayFS）把多层「叠加」成一个统一视图——lowerdir=只读层堆叠，upperdir=可写层，merged=容器看到的合并视图。（《docker题目》里的追问点在这里闭环）

缓存规则（面试高频）

构建时自上而下逐条比对：==某条指令变了 → 该层及其之后所有层全部重建==，缓存失效。

推论：稳定的指令放前面，易变的放最后。典型范式——依赖与源码分离：

反例：先 COPY . . 再装依赖 → 改一行源码，依赖全部重装，构建从 30 秒变 5 分钟。

进阶：BuildKit（DOCKER_BUILDKIT=1）支持并行构建、RUN --mount=type=cache 挂载构建缓存（如 npm/pip 缓存目录），CI/CD 项目里实测过收益。

指令速查表

指令 作用 产生层 关键注意点
FROM 指定基础镜像，必须是第一条 是（基础） 尽量用官方小镜像：alpine / slim
RUN 在构建期执行命令（装软件等） 是 shell 形式 RUN yum install -y x；exec 形式 RUN ["yum","install","-y","x"]
COPY 从上下文复制文件进镜像 是 ==首选 COPY==，语义单纯
ADD COPY + 自动解压 tar + 支持 URL 是 功能多=坑多，一般不用
WORKDIR 设置后续指令的工作目录 否 用绝对路径；不存在会自动创建
ENV 设置环境变量（构建期+运行期都生效） 否 ENV NODE_ENV=production
ARG 构建期变量，==运行期不存在== 否 docker build --build-arg v=1
EXPOSE 声明容器要用的端口 否 ==只是文档/元数据，不做端口映射==，真正映射靠 docker run -p
VOLUME 声明匿名挂载点 否 数据要持久/共享时显式 -v 挂载更可控
USER 指定后续指令及运行时的用户 否 生产镜像避免 root 运行
HEALTHCHECK 定义容器健康检查命令 否 退出码 0/1 判定 healthy/unhealthy
LABEL 附加元数据 否 版本、维护者等
CMD 容器启动的==默认命令== 否 可被 docker run 参数整体替换
ENTRYPOINT 容器启动的==固定入口== 否 参数替换 CMD 后拼接到它后面

CMD vs ENTRYPOINT（重点面试题）

对比项 CMD ENTRYPOINT
定位 默认命令（可被替换） 固定入口程序（雷打不动）
docker run img 不带参数 执行 CMD 执行 ENTRYPOINT（CMD 若有则作为它的默认参数）
docker run img 参数... ==被整体替换== ==不变==，参数替换 CMD 后追加给它
单独使用的短板 传参就废（见图中红叉行） 想换默认参数不方便

两者都有两种写法：

  • ==exec 形式（推荐）==：CMD ["nginx", "-g", "daemon off;"] —— 直接执行，你的进程就是 PID 1，能正确收到 SIGTERM（docker stop 优雅退出）
  • shell 形式：CMD nginx -g "daemon off;" —— 实际是 /bin/sh -c "..."，==sh 成为 PID 1==，信号转发有坑（进程收不到 stop 信号，只能等 10 秒被强杀）
  • 坑：两个都用 shell 形式时，CMD 会被 ENTRYPOINT 忽略——所以==组合使用必须都用 exec 形式==

最佳实践（面试加分项）

  1. 多阶段构建（multi-stage）：构建工具留在构建阶段，运行镜像只拿产物，体积大幅缩小
  1. 合并 RUN 减少层数，且==清理动作必须和安装在同一层==：RUN yum install -y x && yum clean all（分层只增不改，跨层删文件不减小体积）
  2. 基础镜像==固定版本==（node:20-alpine），别用 latest——不可复现 + 缓存永远失效
  3. EXPOSE 不等于端口映射，运行时仍需 -p 8080:3000
  4. 每条指令前想一遍：「这条会不会打断缓存？」
