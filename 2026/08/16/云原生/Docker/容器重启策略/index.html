容器重启策略

是什么

容器的生命周期绑定在==主进程（PID 1）==上：主进程退出，容器就停止。重启策略（--restart）决定主进程退出后 Docker daemon 要不要把它拉起来，以及 daemon 自己重启后要不要拉起容器。

四种策略

策略 触发条件 典型场景
no（==默认值==） 任何情况都不重启 一次性调试、docker run -it 交互
on-failure[:N] 仅==退出码 ≠ 0== 时重启，可限制最多 N 次 批处理/一次性任务（正常结束就不该再跑）
always 无论退出码，一律重启；daemon 重启后也自动拉起 必须常驻的服务
unless-stopped 同 always，但==尊重你的手动 docker stop== ==长期服务首选==

always vs unless-stopped（唯一考点）

==唯一区别发生在 Docker daemon（服务）重启之后==：

  • always：连你之前手动 docker stop 的容器也会被复活
  • unless-stopped：你手动停过的就保持停止，不再自动拉起

场景：你半夜手动停了某容器排查问题，结果服务器重启/daemon 重启，always 的容器自己活了——unless-stopped 就是防这种”背刺”的。

另外：no 和 on-failure 的容器在 daemon 重启后不会被自动拉起。

用法

注意 on-failure 依赖==进程退出码==：你的应用必须异常时以非 0 码退出才能触发，如果程序崩了但退出码还是 0，Docker 会认为它是”正常结束”。

与 Kubernetes 对照

维度 Docker Kubernetes
配置位置 docker run --restart Pod spec 的 restartPolicy
取值 no / on-failure / always / unless-stopped ==Always（默认）/ OnFailure / Never==
作用范围 单个容器 ==Pod 内所有容器==
没有 unless-stopped — K8s 哲学：Pod 该不该存在由==控制器/声明式配置==决定，不存在”手动停一下”的概念
失败节奏 立即重试 kubelet 按==指数退避==重试：10s→20s→40s…上限 5 分钟，这就是 CrashLoopBackOff 的来源

一句话总结：Docker 里你手动管容器自愈；K8s 里自愈是 kubelet 的默认义务，”要不要这个应用”交给声明式配置和控制循环。
