Docker 与虚拟化

一句话结论

==虚拟机虚拟的是「硬件」，容器虚拟的是「操作系统」==。虚拟机每台自带独立内核，容器共享宿主内核——这一个区别推导出启动速度、体积、隔离强度的所有差异。

类比：虚拟机是==独栋别墅==（自带全套水电暖，隔离彻底但造价高）；容器是==合租房的单间==（共用大楼的水电管线=内核，每间只隔一道墙=Namespace，便宜快但隔音差）。

虚拟化分类与常见工具

按虚拟化层次分三类：

类型 原理 代表工具 特点
Type 1 裸金属型 Hypervisor 直接跑在硬件上 VMware ESXi、KVM、Hyper-V、Xen、PVE（KVM+LXC 的管理平台） 性能损耗小，数据中心主流
Type 2 宿主型 Hypervisor 作为某操作系统上的程序 VMware Workstation、VirtualBox、Parallels 安装方便，开发调试用，性能差
OS 级虚拟化 共享内核，靠内核特性隔离进程 Docker、LXC/LXD、OpenVZ 最轻，即容器

常见工具盘点（面试能叫出名字+定位即可）：

工具 类型 一句话定位
VMware ESXi / vSphere Type 1 企业私有虚拟化市占第一，vCenter 统一管理
KVM + QEMU Type 1 Linux 内核内置的虚拟化模块，开源主流；==我的 PVE 底层就是 KVM==
Hyper-V Type 1 微软，Windows Server 自带
Xen Type 1 老牌，支持半虚拟化（改造 Guest OS 换性能）
VirtualBox / Workstation Type 2 个人桌面练手
OpenStack 平台 不是 Hypervisor，是管理大量 KVM 虚拟机的 IaaS 云平台
Docker OS 级 容器事实标准（镜像格式/生态），K8s 时代的”打包工具”
containerd / CRI-O OS 级 K8s 直连的轻量容器运行时（见下文演进）
Podman OS 级 Red Hat 的 Docker 替代：无 daemon、可 rootless
Kata Containers 混合 每个容器/Pod 套一层轻量虚拟机，兼得隔离与容器体验

Docker vs 虚拟机 详细对比

维度 虚拟机 Docker 容器
虚拟化对象 硬件（CPU/内存/设备全模拟） 操作系统（内核提供的视图）
操作系统 每台 VM 一个完整 Guest OS ==共享宿主 Linux 内核，无 Guest OS==
启动速度 分钟级（要引导 OS） ==秒级/毫秒级（只是启动进程）==
体积 GB 级 MB 级
隔离强度 强（独立内核，互相完全不可见） 较弱（Namespace 是”视图隔离”，内核漏洞可能逃逸）
单机密度 几十台 成百上千个
跨 OS VM 内可跑任意 OS（Windows/Linux） ==只能跑与宿主内核兼容的系统==（Linux 容器跑在 Linux 内核上）
隔离手段 Hypervisor 硬件辅助（VT-x） Namespace（pid/net/mnt/uts/ipc）+ Cgroups（资源限额）

两个高频追问：

  1. 为什么容器隔离弱？ 因为大家共用同一个内核——一个内核提权漏洞可能影响所有容器（容器逃逸）。所以金融等强隔离场景会上 Kata / 轻量 VM 方案。
  2. 我在 Windows/Mac 上跑 docker 不也能跑 Linux 容器？ 因为 Docker Desktop 偷偷开了一个==轻量 Linux 虚拟机==（Windows 走 WSL2），容器实际跑在那个 VM 的 Linux 内核上。”容器共享内核”这句话只在真正的 Linux 宿主上成立。

为什么云原生选择了容器

容器对编排系统几乎是量身定做：

  • ==秒级启动== → K8s 才能随意扩缩容、滚动更新、失败重建
  • ==镜像=标准交付物== → “build once, run anywhere”，GitOps 有了可声明的对象
  • ==MB 级体积+高密度== → 一台节点跑上百 Pod，资源利用率碾压 VM

DaoCloud DCE 这类平台的底座就是：物理机/VM → K8s → containerd → 容器。

容器运行时演进（面试常问”docker 和 containerd 什么关系”）

  • Docker 把容器管理部分捐给了 CNCF，成为 ==containerd==（现在 K8s 节点上真正干活的就是它，我在集群里用 crictl/ctr 操作的就是 containerd）
  • runc 是最底层的 OCI 标准运行时，真正调 Namespace/Cgroups 创建容器
  • 一句话回答：==Docker 是”镜像格式+构建+生态”的事实标准，K8s 的运行时代码路径已经不需要 dockerd==
