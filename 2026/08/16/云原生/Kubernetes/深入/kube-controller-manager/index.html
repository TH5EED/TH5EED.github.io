kube-controller-manager

发表于2026-08-16|更新于2026-08-16|云原生
|浏览量:

介绍

  • 控制器，负责运行一些后台控制循环，并监视系统中的各个资源的状态

  • 通常运行到master/controll plane节点，包含多个控制器实例（如rs控制器，deploy控制器，node控制器，HPA等），每个控制器负责处理不同的资源

  • 控制器实例以多个独立的控制回路运行

控制回路/循环

所有控制器都遵循一个通用的编排模式，即控制回路

  • kube-controller-manager启动后会成为一个进程

  • 内部会为每一种控制器启动一个独立的的轻量级线程goroutin

  • 每个轻量级线程goroutin运行着对应控制器的控制回路，并发执行，共享进程的内存空间，但逻辑独立

Q：为什么这样设计，不能每个控制器都是一个进程吗

  • 节省资源：如果每个控制器都运行一个独立进程，那么每个进程都要与 API Server 建立连接、维护认证信息，开销大。放在一个进程里，可以共享连接池、缓存等。

  • 便于管理：管理员只需管理一个组件（启动、停止、配置），而不是几十个。

  • 并发安全：通过 Informer 的本地缓存和 workqueue 机制，避免竞争条件。
