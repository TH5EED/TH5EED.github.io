通过 ctr 挂载镜像提取 etcdctl

发表于2026-08-16|更新于2026-08-16|云原生
|浏览量:

📌 核心概念与原理

在 Kubernetes 集群运维中，我们经常需要操作 etcd（如备份、恢复、查看键值）。但在某些精简版的 Kubernetes 安装（如 kubeadm）或容器化部署中，宿主机上可能没有安装 etcdctl 客户端工具。

这招属于： 容器运行时层级的镜像内省与内容提取。

它利用了 containerd 的 ctr 工具，绕过 Docker 或 Kubelet，直接将镜像的文件系统层（Layer）挂载到宿主机目录。这允许我们在不启动容器的情况下，直接访问镜像内的二进制文件。

⚠️ 使用前提与注意事项

  • 权限要求：必须拥有宿主机的 root 权限或 sudo 权限。
  • 运行时环境：节点必须使用 containerd 作为容器运行时（如果是 Docker-shim 或 CRI-O，命令略有不同）。
  • 命名空间陷阱：
    • crictl 看到的镜像通常属于 CRI 管理的命名空间（通常是 k8s.io）。
    • ctr 默认查看的是 default 命名空间。
    • 关键点：必须使用 -n k8s.io 参数指定命名空间，否则会报错 image not found。
  • 镜像状态：目标镜像（如 etcd）必须已经存在于节点上（通常 etcd 组件运行时，其镜像已拉取）。

💡 常见问题排查

  • 报错 image not found：
    • 原因：未指定 -n k8s.io 或镜像名称不匹配。
    • 解决：使用 ctr -n k8s.io images list | grep etcd 确认确切名称。
  • 报错 certificate signed by unknown authority：
    • 原因：未配置 CA 证书或路径错误。
    • 解决：检查 ETCDCTL_CACERT 环境变量指向的文件是否存在。
  • 报错 permission denied：
    • 原因：权限不足。
    • 解决：确保使用 sudo 执行 ctr 和 cp 命令。
