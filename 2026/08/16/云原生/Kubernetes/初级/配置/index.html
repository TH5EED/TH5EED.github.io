跨服务内部文件一致方法

共享

（附件缺失：../assets/配置/Pasted%20image%2020260630104511.png）

共享服务器安装NFS服务，在多个服务所在机器安装NFS客户端，将共享目录挂载到本地目录

每次读取时，都会发生网络IO

没有文件大小限制

注入

（附件缺失：../assets/配置/Pasted%20image%2020260630105215.png）

共享服务器一次注入后，多次读取，不再消耗网络IO

注入到nginx所在服务器本地，读取本地

注入是一次性的，静态的

只有将cm挂载为volume时，才可以热更新，并且环境变量不支持热更新

ConfigMap

定义

  • 非敏感的配置数据：环境变量，配置文件

  • 明文形式

  • 不超过1MiB

  • 以注入方式将数据传递给pod

流程
kubelet解析yaml，发现环境变量引用的cm的键，向api-server发送请求，拉取该cm的数据，转换为操作系统的环境变量格式，写入即将启动的容器进程的运行时环境中

使用

==复杂用挂载卷，简单用env
env一次注入，后续不会更新==

卷挂载文件

注意：
使用subPath挂载的是单个文件，无法热更新

热更新

挂载后，cm的每个key都会在挂载目录下成为一个文件，文件内容只有对应value

文件类型为软链接，之所以不直接用文件是因为更新文件时如果正好在读取就会出问题，所以采用先创建一个新文件，然后重新链接新文件，这样读取的文件从没改变

  • volumeMounts.name 必须和 volumes.name 一致

  • 挂载后，原目录内容会被覆盖（类似 bind mount）

  • 更新 ConfigMap 后，挂载的文件会自动更新（约 1 分钟延迟），但应用需自行reload

但可以通过修改annotations字段强制触发滚动更新，不一定666666，只要和原来不同即可

所以可以将未来可能会修改的配置文件都抽象在cm资源中，修改后会再挂载回pod内部
避免了重新封装镜像、重新编写控制器

不可更改

热更新会不停监听apiserver，如果确定不改变配置文件，可设置为不可更改immutable:true
设置后，再edit会修改不成功

  • 防止一些错误修改

  • 显著降低apiserver的负载，提升集群性能

不过无法回退，只能删除此cm重新创建一个无该字段的cm

Secret

定义

  • 敏感的数据：密码，OAuth令牌，SSH密钥

  • 编码形式

  • 默认Opaque类型

  • value值被使用时会自动解码，所以写入时一定要编码

热更新

同ConfigMap

注意：
使用secret作为子路径卷挂载的容器不支持热更新，因为挂载的是单个文件不是目录，所以已经写死无法改变

不可更改

同ConfigMap

注入机制 Downward API

  • Downward API是Kubernetes 中的一个功能，它允许容器在运行时从Kubernetes API 服务器获取有关它们自身的信息。

  • 这些信息可以作为容器内部的环境变量、文件注入到容器中，以便容器可以获取有关其运行环境的各种信息，如Pod名称、命名空间、标签等

  • 不同于k get po命令从外部获取，downwardapi机制可以让pod自己知道自己的元数据
