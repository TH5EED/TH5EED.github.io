k8s学习流程

发表于2026-08-16|更新于2026-08-16|云原生
|浏览量:

你已经掌握了 Kubernetes 中核心的 工作负载（控制器） 部分，能够管理各种 Pod 的生命周期和运行模式。接下来，自然要解决 Pod 如何被访问、配置如何管理、数据如何持久化 等问题。我根据实际应用的依赖关系，建议你按以下顺序深入：

🎯 推荐学习路线（由浅入深，每个主题都必备）

顺序 主题 核心作用 为什么在这步学
1 Service 为 Pod 提供稳定的网络访问入口（负载均衡、服务发现） Pod 会重启/漂移，IP 变化，需要固定方式访问
2 Ingress 七层路由（域名、路径转发）到 Service 集群外部 HTTP/HTTPS 流量接入
3 ConfigMap / Secret 将配置、敏感信息与 Pod 解耦 不改镜像就能改配置，避免密码写死
4 Volume & PVC & StorageClass 容器数据持久化（Pod 重启不丢数据） 数据库、日志等场景必须
5 NetworkPolicy Pod 间网络隔离（防火墙规则） 安全性（零信任）必备
6 资源配额 & LimitRange 限制 Pod 的 CPU/内存 防止资源争抢，保证稳定性

1️⃣ Service —— 首先必学

为什么先学 Service？

  • 你已经有能力创建 Deployment / StatefulSet 跑起 Pod，但 Pod 的 IP 是临时的，比如：
    • 滚动更新后 IP 全变
    • 重新调度到另一个节点，IP 也变
  • Service 提供了一个固定的虚拟 IP 和 DNS 名称，作为 Pod 的稳定访问入口。
  • 没有 Service，你只能在集群内部通过 Pod IP 访问（不稳定），外部完全无法访问。

学习要点

  • ClusterIP（默认）：集群内部可达，暴露一个内部 IP。
  • NodePort：在每个节点开放一个端口（30000-32767），供集群外访问。
  • LoadBalancer：配合云厂商提供公网负载均衡器。
  • Headless Service（ClusterIP: None）：为 StatefulSet 提供直接解析到 Pod IP 的 DNS。
  • kube-proxy 的工作模式（iptables / IPVS）可简单了解。

2️⃣ Ingress —— 外部七层路由

为什么接着学 Ingress？

  • Service 的 NodePort 和 LoadBalancer 只能处理四层（TCP/UDP），且每个服务要占用一个端口或一个 LB，成本高。
  • Ingress 可以提供基于域名、路径的七层路由，一个入口（如 nginx 控制器）代理多个后端 Service。
  • 实际生产中，Web 应用基本都用 Ingress 对外暴露。

学习要点

  • Ingress Controller（如 nginx-ingress、Traefik）—— 必须部署一个控制器，Ingress 资源本身只是规则。
  • Ingress 规则：host + path 转发到不同 Service。
  • TLS/HTTPS：通过 Secret 配置证书。
  • 注解（annotations）：配置重写、限流等高级功能。

前置依赖

  • 你已经学过的 Service（Ingress 转发到 Service）。
  • 可能需要了解 kubectl apply -f https://... 部署第三方控制器。

3️⃣ ConfigMap & Secret —— 配置与敏感信息

为什么先学配置再学存储？

  • 配置管理比持久化存储更常用，也更简单。
  • 你已经在 Pod 模板中写死环境变量或命令参数，但想改镜像的配置文件就需要重建镜像，很麻烦。
  • ConfigMap 存储非敏感配置（如日志级别、后端地址）。
  • Secret 存储敏感信息（密码、Token），内容经 base64 编码（注意不是加密）。

学习要点

  • 创建：从字面量、文件、目录创建。
  • 注入方式：
    • 环境变量（env.valueFrom）
    • 卷挂载（volumes + volumeMounts）
  • subPath：挂载单个文件而不覆盖目录。
  • 不可变配置（immutable: true）防止意外修改。

动手示例

4️⃣ 存储（Volume / PVC / StorageClass）—— 数据持久化

为什么放在 Service 和 ConfigMap 之后？

  • 因为你前面学的无状态应用（Deployment）可能不需要持久化存储；StatefulSet 虽然涉及存储，但你已经知道 volumeClaimTemplates。
  • 存储是更偏向有状态场景的知识，但即使是无状态应用也可能需要临时存储（emptyDir）或共享配置。
  • 从基础到高级：emptyDir → hostPath → PersistentVolumeClaim → StorageClass。

学习要点

  • emptyDir：Pod 生命周期内的临时存储。
  • hostPath：挂载宿主机目录（不推荐生产，仅测试）。
  • PersistentVolume (PV) 和 PersistentVolumeClaim (PVC)：
    • 管理员分配存储（PV），用户声明需求（PVC）。
    • PVC 绑定 PV，Pod 使用 PVC。
  • StorageClass：动态创建 PV（云硬盘自动供应），不用手动预分配 PV。

动手顺序

  1. 使用 emptyDir 体验多容器共享临时数据。
  2. 静态 PVC：手动创建 NFS 类型的 PV，然后创建 PVC 绑定，最后挂载到 Pod。
  3. 动态 PVC：安装一个存储插件（如 nfs-subdir-external-provisioner）或云厂商 CSI，定义 StorageClass，Pod 中 PVC 指定 storageClassName。

5️⃣ 附加：NetworkPolicy（网络策略）

为什么学它？

  • 默认 Kubernetes 集群中所有 Pod 之间可以互相通信（扁平网络）。
  • NetworkPolicy 实现了类似防火墙的规则，隔离 Pod。
  • 安全要求高的场景（如多租户、金融行业）必学。

前置条件

  • 集群网络插件必须支持 NetworkPolicy（如 Calico、Cilium、Weave）。
  • 了解 Label（你已学过）用于选择 Pod。

学习要点

  • podSelector：选定要保护的 Pod。
  • policyTypes：Ingress / Egress。
  • ingress.from：允许哪些源（namespaceSelector、podSelector、ipBlock）。
  • egress.to：允许哪些目标。

✅ 你的学习规划建议

按照你目前的控制器深度，推荐接下来的 2~3 周：

阶段 内容 时间分配
第1周 Service（重点） + Ingress 入门 3天 Service，2天 Ingress（部署 nginx-ingress 测试）
第2周 ConfigMap + Secret 2天学概念和练习，3天结合 Deployment 改造现有应用
第3周 存储（emptyDir → hostPath → PVC → StorageClass） 3天基础，2天动态存储实战（如部署一个 MySQL 并持久化数据）
进阶 NetworkPolicy、RBAC、Helm 打包 视兴趣和实际需求安排

推荐学习资源

  • 官方教程：https://kubernetes.io/docs/tutorials/
  • 模拟环境：https://killercoda.com/killer-shell-cka （免费交互练习）
  • 动手项目：用 Deployment + Service + Ingress + ConfigMap 部署一个 WordPress 或 简单 Web 应用，再加上 MySQL 的 StatefulSet 和 PVC。

这样学习，你很快就能独立部署一套完整的、可访问的、有配置管理、有持久化存储的应用。学完这些后，你再接触调度（亲和性、污点容忍）、自动伸缩（HPA）、服务网格（Istio）等高级话题。
