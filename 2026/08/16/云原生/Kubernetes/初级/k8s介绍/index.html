k8s介绍

发表于2026-08-16|更新于2026-08-16|云原生
|浏览量:

优势

  • 服务发现和负载均衡
    创建一个svc资源即可替代“手动搭建nginx作为负载调度器，用户请求被负载到不同的apache”

  • 存储编排（添加任何本地或云服务器）
    一条命令就可以使用存储的资源；云服务器还可以按量收费

  • 自动部署和回滚
    定义一个job检测远程代码仓库，有更新就调用k8s接口实现自动部署；回滚版本

  • 自动分配CPU/内存资源-弹性收缩
    自动挑选最合适节点

  • 自我修复（需要时启动新容器）
    重启pod代价足够小

  • secret和配置管理
    敏感信息编码

  • 支持大型规模

  • 开源

微观架构

微观架构图

组件

  • API Server k8s的核心接口和控制中枢，负责处理所有外部请求和内部组件通信

    • web UI
      官方本身不配置，但可以安装dashboard组件

    • kubectl 客户端工具

    • Scheduler 控制器

    • Controller Manager(Replication Controller) 调度器

  • etcd 分布式键值存储来自API Server理解的数据，持久化保存集群的完整状态数据，
    Raft选举机制保证高可用，需要节点奇数个

  • kubelet 承上启下，连接API Server与容器运行时，负责 Pod 的生命周期管理（创建、监控、删除）

  • kubeproxy 承上启下，负责 Service 的网络代理和负载均衡，实现集群内部网络通信

插件

k8s通过标准化接口实现”即插即用”的扩展机制

  • CoreDNS
    集群内部域名解析服务

  • Ingress Controller
    官方提供Service四层负载均衡，Ingress可以实现七层（HTTP/HTTPS） 负载均衡和路由

接口类型 全称 作用 常见实现
CRI Container Runtime Interface 容器运行时接口 containerd, CRI-O, Docker（需要适配器）
CNI Container Network Interface 网络插件接口 Calico, Flannel, Cilium
CSI Container Storage Interface 存储插件接口 NFS, Ceph, AWS EBS

容器运行时

  • containerd与docker两个运行时的区别在于：前者摒弃掉了cri-docker→dockerd这一流程，负担更少

  • 所以如果使用docker，要有一个cri转换ocri的工具：cri-docker
    kubelet→cri-docker→dockerd→containerd→runc→my-app-container

  • cri-o是专为k8s而生，完全独立与docker

附件

  • Prometheus

  • DashBoard

  • Federation
