存储相关复习

发表于2026-08-16|更新于2026-08-16|云原生
|浏览量:

根据您之前对 MySQL 实例 Pod 存储概念的讲解，我理解您希望对 PostgreSQL 实例也做类似的存储结构分析。以下以 QFusion 中一个 PostgreSQL 实例 Pod 为例，逐一解释其存储相关字段。

一、PostgreSQL 实例 Pod 简化 YAML（存储相关部分）

apiVersion: v1
kind: Pod
metadata:
 name: postgres-e037ddb-0-0
 namespace: default
spec:
 containers:
 · name: postgres
  image: postgres:15.7
  volumeMounts:
  · name: data                     # 数据目录
   mountPath: /pgdata
  · name: wal                      # WAL 日志目录
   mountPath: /pgwal
  · name: log                      # PG 日志目录
   mountPath: /pglog
  · name: conf                     # 配置文件
   mountPath: /pgconf
  · name: conf-custom              # 自定义配置
   mountPath: /pgconf_custom
  · name: tmp                      # 临时文件
   mountPath: /tmp
  · name: secret-volume            # 密码/证书
   mountPath: /run/secrets
   readOnly: true
 · name: exporter                   # 监控采集容器
  volumeMounts:
  · name: conf
   mountPath: /pgconf
   readOnly: true
 volumes:
 · name: data                       # 持久化数据（hostPath）
  hostPath:
   path: /data/postgres/postgres-e037ddb/data
   type: DirectoryOrCreate
 · name: wal                        # WAL 日志（hostPath）
  hostPath:
   path: /data/postgres/postgres-e037ddb/wal
   type: DirectoryOrCreate
 · name: log                        # 运行日志（hostPath）
  hostPath:
   path: /data/postgres/postgres-e037ddb/log
   type: DirectoryOrCreate
 · name: conf                       # 配置文件（ConfigMap）
  configMap:
   name: postgres-e037ddb-config
 · name: conf-custom                # 自定义配置（ConfigMap）
  configMap:
   name: postgres-e037ddb-custom-config
 · name: tmp                        # 临时空间（emptyDir）
  emptyDir: {}
 · name: secret-volume              # 敏感信息（Secret）
  secret:
   secretName: postgres-e037ddb-secret

二、逐字段解释（与 MySQL 对比讲解）

1. ConfigMap（配置映射）

在 PG 中的表现：
· conf 卷 → 挂载到 /pgconf，包含 postgres.base.conf、postgres.sys.conf 等基础配置
· conf-custom 卷 → 挂载到 /pgconf_custom，存放用户自定义的配置覆盖文件

进入 Pod 后查看：
[postgres@postgres-e037ddb-0-0 ~]$ ls /pgconf/
pgrouter  pgsuper  pguser  postgres.base.conf  postgres.sys.conf  tls

与 MySQL 的不同：

特性 MySQL PostgreSQL
ConfigMap 挂载点 /etc/mysql/conf.d /pgconf 和 /pgconf_custom
配置文件名 my.cnf postgres.base.conf + postgres.sys.conf
自定义配置 直接修改 ConfigMap 通过 conf-custom 独立管理

2. hostPath（主机路径）

在 PG 中的表现：
· data 卷 → /data/postgres/postgres-e037ddb/data → 挂载到 /pgdata
· wal 卷 → /data/postgres/postgres-e037ddb/wal → 挂载到 /pgwal
· log 卷 → /data/postgres/postgres-e037ddb/log → 挂载到 /pglog

进入 Pod 后查看：
[postgres@postgres-e037ddb-0-0 ~]$ df -h | grep -E “(pgdata|pgwal|pglog)”
/dev/nvme0n1  1.9T  84G  1.8T   5% /pgdata
/dev/nvme1n1  1.9T  12G  1.8T   1% /pgwal
/dev/nvme0n1  1.9T  84G  1.8T   5% /pglog

与 MySQL 的对比：

目录 MySQL PostgreSQL 说明
数据目录 /var/lib/mysql /pgdata/data PG 的数据文件在 /pgdata/data 子目录下
日志目录 /var/log/mysql /pglog PG 日志文件为 postgresql-YYYY-MM-DD_HH.csv 格式
事务日志 无独立目录 /pgwal PG 的 WAL 日志独立存储，MySQL 的 binlog 在数据目录内

PG 特有的目录结构：
/pgdata/                    # 数据目录（hostPath）
├── data/                  # 实际的数据库数据
│   ├── base/             # 数据库文件
│   ├── global/           # 全局系统表
│   ├── pg_wal/           # WAL 日志（软链接到 /pgwal）
│   └── postgresql.conf   # 主配置文件
├── postgres-e037ddb/     # 备份相关
└── all.sql               # 用户导出的备份文件

/pgwal/                    # WAL 日志目录（独立 hostPath）
├── 000000010000000000000001
└── archive_status/

/pglog/                    # 运行日志目录（独立 hostPath）
├── postgresql-2025-08-03_000000.csv
├── postgresql-2025-08-03_010000.csv
└── postgresql-2025-08-03_020000.log

3. Secret（机密）

在 PG 中的表现：
· 挂载到 /run/secrets，包含多个密码文件

进入 Pod 后查看：
[postgres@postgres-e037ddb-0-0 ~]$ ls /run/secrets/
MYSQLROOTPASSWORD   # 注意：PG 也保留了 MySQL 的命名习惯
PGMONITOR_PASSWORD    # 监控用户密码
PGHAPASSWORDTYPE    # 高可用密码类型

查看密码内容：
[postgres@postgres-e037ddb-0-0 ~]$ cat /pgconf/pgsuper/password
7qa1faW5orCospk

PG 特有的密码文件位置：
· /pgconf/pgsuper/password → postgres 超级用户密码
· /pgconf/pguser/password → 普通用户密码
· /pgconf/pgreplicator/password → 复制用户密码

4. emptyDir（空目录）

在 PG 中的表现：
· 挂载到 /tmp，用于临时排序、临时表等操作

进入 Pod 后查看：
[postgres@postgres-e037ddb-0-0 ~]$ df -h /tmp
Filesystem      Size  Used Avail Use% Mounted on
tmpfs           189G     0  189G   0% /tmp

与 MySQL 的不同：
· PG 的 emptyDir 使用 tmpfs（内存文件系统），速度更快
· MySQL 的 emptyDir 默认使用本地磁盘

5. mountPath（挂载路径）

PG 的完整挂载结构：

容器内路径 卷名称 存储类型 用途
/pgdata data hostPath 数据库数据文件
/pgwal wal hostPath WAL 事务日志
/pglog log hostPath 运行日志
/pgconf conf ConfigMap 基础配置
/pgconf_custom conf-custom ConfigMap 自定义配置
/tmp tmp emptyDir 临时文件
/run/secrets secret-volume Secret 密码/证书

6. subPath（子路径）

在 PG 中的特殊用法：

PG 的 data 卷没有使用 subPath，因为 PG 的数据目录结构本身就是 /pgdata/data/，这个 data 子目录是 PG 初始化时自动创建的。

对比 MySQL：
· MySQL 使用 subPath: mysql-data 来隔离数据
· PG 通过目录结构自然隔离（/pgdata/data/）

三、进入 Pod 后的实际效果

当您通过 QFusion 的远程终端进入 PG 实例 Pod 后：

查看所有挂载点
[postgres@postgres-e037ddb-0-0 ~]$ mount | grep -E “(pgdata|pgwal|pglog|pgconf|tmp|secrets)”
/dev/nvme0n1 on /pgdata type ext4 (rw,relatime)
/dev/nvme1n1 on /pgwal type ext4 (rw,relatime)
/dev/nvme0n1 on /pglog type ext4 (rw,relatime)
tmpfs on /pgconf type tmpfs (ro,relatime)        # ConfigMap 只读
tmpfs on /pgconf_custom type tmpfs (ro,relatime) # ConfigMap 只读
tmpfs on /tmp type tmpfs (rw,relatime)           # emptyDir
tmpfs on /run/secrets type tmpfs (ro,relatime)   # Secret 只读

四、总结对比表（MySQL vs PostgreSQL）

概念 MySQL 对应 PostgreSQL 对应 关键差异
ConfigMap /etc/mysql/conf.d /pgconf + /pgconf_custom PG 将基础配置和自定义配置分离
hostPath 数据 /var/lib/mysql /pgdata PG 数据在 /pgdata/data 子目录
hostPath 日志 /var/log/mysql /pglog PG 日志为 CSV 格式
hostPath WAL 无（binlog 在数据目录） /pgwal PG 将 WAL 独立存储
Secret /etc/mysql/secret /run/secrets + /pgconf/*/password PG 同时使用两种方式
emptyDir /tmp（磁盘） /tmp（tmpfs 内存） PG 默认使用内存文件系统
subPath 使用（mysql-data） 不使用 PG 通过目录结构自然隔离

五、PG 特有的存储特点

1. WAL 独立存储：PG 将重做日志（WAL）放在独立的 hostPath 卷 /pgwal，而 MySQL 的 binlog 在数据目录内。这有利于 WAL 归档和备份恢复。

2. 日志格式：PG 的日志文件是 CSV 格式（postgresql-YYYY-MM-DD_HH.csv），便于导入分析工具。

3. 密码管理：PG 除了 Secret 卷外，还在 /pgconf/ 下提供了独立的密码文件，方便不同用户（super/user/replicator）使用。

4. 配置分层：通过 pgconf（基础配置）+ pgconf_custom（自定义配置）实现配置的灵活管理。

如果您想进一步了解 PG 的备份恢复、WAL 归档或连接数修改等操作，可以继续提问。
