进程

程序是静态的代码文件，进程是程序运行中的动态实例
每个进程有唯一的PID（进程ID），由系统分配

==Linux中进程是树状结构的，init/systemd是所有进程的祖先（PID 1）==
详见systemd

ps

process status，查看进程快照信息

aux 输出字段

字段 含义
USER 进程所属用户
PID 进程ID
%CPU CPU占用率
%MEM 内存占用率
VSZ 虚拟内存用量（KB）
RSS 物理内存用量（KB）
TTY 终端（?表示与终端无关，如守护进程）
STAT 进程状态
START 进程启动时间
TIME 累计CPU时间
COMMAND 启动该进程的命令

STAT 进程状态

状态 含义
R 运行
S 可中断睡眠
D 不可中断睡眠
Z 僵尸进程
T 停止
s 会话首进程
+ 前台进程
l 多线程

top

实时查看系统资源和进程，详见系统监控与信息

kill

向进程发送信号

信号 编号 含义
SIGHUP 1 挂起，重载配置
SIGINT 2 中断（Ctrl+C）
SIGTERM 15 终止（默认）
SIGKILL 9 强制杀死

==kill -9是最后手段，进程来不及清理资源，可能导致数据丢失或僵尸进程==

killall

按进程名杀死

pkill

按模式匹配杀死，更灵活

后台作业管理

&

命令后加&，放入后台运行

nohup

no hang up，终端关闭后进程不退出

==&只是后台运行，终端关闭后仍会退出；nohup + & 才是真正的守护式运行==

jobs

查看当前终端的后台作业

fg / bg

Ctrl+Z 将前台进程暂停并放入后台，然后可用bg继续在后台运行

优先级

nice

启动时指定优先级

nice值范围：-20（最高）到19（最低），默认0
==只有root才能提高优先级（负值），普通用户只能降低==

renice

修改已运行进程的优先级

延伸

K8s中的进程与组件关系：组件与进程关系

systemd
介绍是Linux系统中现代的init进程，即1号进程；也是服务管理器 系统启动后第一个运行的进程（PID 1） 管理系统上所有的服务（daemon），比如 sshd、nginx、docker、kubelet 等 提供并行启动、依赖管理、日志记录（journald）、资源控制等功能 systemctl是systemd的用户命令行工具 使用作为 systemd 服务：写一个 .service 文件，由 systemd 负责启动、监控、重启。 例如 kube-proxy.service，然后用 systemctl start kube-proxy 启动。

模块
加载模块命令12345# 立即加载 overlay 模块modprobe overlay # 立即加载 br_netfilter 模块modprobe br_netfilter overlay 作用：提供 OverlayFS 联合文件系统支持 在 K8s 中的意义：containerd 使用 OverlayFS 来构建容器的文件系统层级。容器的镜像是分层存储的，OverlayFS 能把多个只读层叠加，再在上面加一个可写层，实现”写时复制”。没有这个模块，containerd 无法正常创建容器的根文件系统，Pod 会启动失败。 br_netfilter 作用：让 Linux 网桥上的流量能被 iptables 规则过滤 在 K8s 中的意义：K8s 的 Pod 网络和 Service 转发大量依赖 iptables。Pod 之间通信数据会经过网桥（如 cni0），如果不加载此模块，这些流量会绕过 iptables，导致 Service 的 ClusterIP 无法访问、Pod 网络策略失效。
