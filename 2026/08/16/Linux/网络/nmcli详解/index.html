速记

  • 在网卡目录下操作，无论增删改，生效都需要执行nmcli c reload，将连接配置同步到内存中

  • 使用nmcli c mod xxx操作，生效分为两种：
    修改IP等需要nmcli c up xxx重连
    修改DNS只需热更新nmcli d reapply xxx

它们与 systemctl restart NetworkManager 的关系

当你执行 systemctl restart NetworkManager 时，服务会强制对所有设备执行如下操作序列：

  1. 对所有设备执行隐式的 d down（清理一切，网络全断）。

  2. 重启进程，重新读取所有配置文件。

  3. 对所有设备执行隐式的 d up（拉起物理链路）。

  4. 针对所有设置了 autoconnect=yes 的连接，自动逐个执行 c up（恢复网络）。

这解释了一个重要结论：systemctl restart = 全局强制 d down + 全局强制 d up + 全局批量 c up。因此，它的破坏力远大于任何单个 nmcli 命令。

目标：学完能应付 90% 的 Linux 网络管理场景（查状态、改 IP、改 DNS、控网关、排错）。
偏门/内核级细节（rp_filter、ARP flux、ECMP 内部、altname 等）这里不展开，需要时再查。

一、先记住一个核心模型：设备 ≠ 连接

  • device（设备）：物理/虚拟网卡硬件，比如 ens160、ens224。
  • connection（连接）：一套网络配置（IP、DNS、网关、是否自启）。它是软件层面的”配置文件”。
  • 关键规则：一个设备上可以同时存在多个连接，但同一时间只能有 1 个被激活。 切换网络环境 = 切换连接。

类比：设备像一台音响（硬件），连接像不同的音源（CD/蓝牙/收音机）。一台音响同时只能放一个音源，但你可以存好几套音源随时切换。

常用区别：

想做的事 命令 说明
看网卡状态 nmcli d status 看所有硬件网卡
看连接配置 nmcli c show 看所有保存的配置
激活某个配置 nmcli c up "名称" 把配置应用到对应网卡
让 NM 自动连网卡 nmcli d connect ens160 NM 自动找合适配置来激活

二、五个对象一句话

对象 缩写 管什么
general g NM 整体状态、主机名
networking n 系统总开关（nmcli n off 全断网）
radio r 无线开关（Wi-Fi/WWAN），不影响有线
connection c 连接配置：增删改查、激活停用
device d 网卡硬件：状态、连接/断开、重应用

四、改了配置怎么让它生效（重点）

两种生效方式，区别很大：

方式 命令 表现 适用
重激活 nmcli c up ens160 先断网卡再连上 改了 IP/网关这种必须重连的
热重应用 nmcli d reapply ens160 不中断连接刷新配置 只改 DNS 等不想断 SSH 时

如果你是用 vi 直接改了 /etc/NetworkManager/system-connections/xxx.nmconnection 文件，
必须先把改动告诉 NM：nmcli c reload（重读所有文件），再 c up 或 d reapply。
否则你改了文件，NM 不知道，配置不会变。

五、最常做的几件事（配方）

1) 设置静态 IP（以 ens160 为例）

2) 改成 DHCP

3) 改 DNS（不中断 SSH 用 reapply）

4) 控制默认网关走哪张卡（route-metric，越小越优先）

5) 多网卡时让”副卡”别抢网关/DNS

6) 改主机名

要点：

  • 文件名随意，但 [connection] 里的 id 才是 nmcli c 里看到的名字。
  • interface-name 把配置绑死到某张网卡，避免搞混。
  • 改这个文件后记得 nmcli c reload 再 up/reapply。

七、改了不生效？排查顺序

==用 vi 改的文件 → 先 nmcli c reload，再 c up / d reapply。==
==用 nmcli c mod 改的 → c up（要重连）或 d reapply（不重连）。==
==删了磁盘文件 nmcli c show 还在 → 配置还在内存里，执行 nmcli c reload 同步，或 nmcli c delete "名称" 彻底删。==
配置”生效了但行为不对” → 看实际状态，别只看配置：
ip -4 a、ip route show、cat /etc/resolv.conf。

ens224 / ens256 = DHCP，分别 192.168.72.132 / .133；三张卡都在 192.168.72.0/24。
注意：你的 SSH 大概率在 ens160 上，nmcli c up ens160 会短暂断线，改 ens160 时优先用 nmcli d reapply。

实验 2：让 ens160 稳坐默认网关（route-metric）

实验 3：clone 抢占，验证”一张卡只能跑一个连接”

实验 4：把一张 DHCP 卡改成静态 IP

实验 5：看清你现在的”真相”（诊断三连）

九、速查口诀

  • 看 → nmcli d status / nmcli c show / ip -4 a / ip route
  • 改 → nmcli c mod 名称 参数
  • 生效 → 要重连用 c up，不想断用 d reapply；改文件要 c reload
  • 删 → nmcli c delete 名称（别只删文件）
  • 多网卡抢网关 → ipv4.route-metric 调大小，或副卡 ipv4.never-default yes
