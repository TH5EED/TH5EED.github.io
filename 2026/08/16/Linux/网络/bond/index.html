网卡绑定（bond）实用笔记

风格与本目录的 nmcli实用笔记.md 一致：先讲清楚是什么/为什么，再给能直接照做的实验。
全部命令基于 NetworkManager（nmcli），适用于 Rocky9 / RHEL9。
实验环境见第四节，核心是：别绑 ens160（你的 SSH 在那），绑 ens224 + ens256。

一、先搞懂：bond 是什么、解决什么问题

bond（网卡绑定 / 链路聚合） 把多块物理网卡聚合成一个逻辑网卡（通常叫 bond0），对外只呈现一个 IP、一个 MAC。

它解决两件事：

  1. 链路冗余：一张网卡/网线挂了，流量自动切到另一张，网络不断。
  2. 提升带宽（部分模式）：多张卡的带宽叠加。

对比你之前学的”多网卡同子网”：那是多归属主机，会抢默认网关、ARP 混乱；bond 是把多张卡合成一个口，对外只有一个地址，从根上避免了那些问题。

二、bond 的几种模式（重点看 mode 1）

模式 nmcli 写法 作用 需要交换机配合？ 适合你吗
0 balance-rr mode=0 轮询发包，增带宽 否（但易乱序） 了解即可
1 active-backup mode=1 一主一备，挂了切备用 否 ✅ 首选，VM 最合适
2 balance-xor mode=2 按哈希选卡 否 少用
3 broadcast mode=3 所有卡都发一份 否 特殊场景
4 802.3ad mode=4 标准 LACP 聚合 是（需 vSwitch 开 LACP） 进阶再玩
5 balance-tlb mode=5 自适应发送负载 否 少用
6 balance-alb mode=6 收发都自适应 否 少用

学习建议：先把 mode 1（active-backup） 玩透——它不需要任何交换机配置，在 VM 里就能完整体验”故障切换不丢包”，最能体现 bond 的价值。

三、关键参数（动手前先明白）

这些参数写在 bond.options 里：

  • miimon=100：每 100 毫秒探测一次从卡链路。值越小，发现故障越快（也略费资源）。决定 failover 速度。
  • fail_over_mac=1（VM 专属，推荐）：active-backup 下，默认 0 是”bond 用当前 active 从卡的 MAC，切换时换 MAC”——VM 里每张虚拟网卡 MAC 不同，切换瞬间可能闪一下 ARP。设 1 让 bond 固定用自己的 MAC，切换更平滑。
  • updelay / downdelay：链路”起来/down”后延迟多少毫秒才认定，避免因抖动频繁切换。初学可不设。
  • active_slave=ens256：指定主卡（可选）。

四、你的实验环境（贴合实际）

安全原则：bond 只在 ens224 + ens256 上做。ens160 全程保留，SSH 不断，你随便折腾。

这一步会多出 3 个配置文件（bond0.nmconnection、bond0-port-ens224.nmconnection、bond0-port-ens256.nmconnection），正好呼应你之前学的”连接为什么会落盘到 system-connections/“。

六、验证 bond 是否成功

/proc/net/bonding/bond0 里重点看两行：

  • Bonding Mode: active-backup —— 模式对
  • Active Port: ens224 —— 当前主卡是谁

十、速查口诀

  • 是什么：多卡合成一个逻辑口，一个 IP 一个 MAC，冗余或增带宽。
  • 学哪个：先玩 mode=1 active-backup，VM 不用配交换机。
  • 怎么建：nmcli c add type bond ... → 配 IP → 两张卡 slave-type bond master bond0 → up。
  • 怎么验：cat /proc/net/bonding/bond0。
  • 怎么秀：nmcli d disconnect 一张从卡，ping 不丢 = 成功。
  • VM 坑：fail_over_mac=1 让 bond 固定自身 MAC，failover 不闪 ARP。
