文件系统

定义

管理数据存储和检索的软件模块，本质是一种数据结构，负责组织，存储和检索文件

必须构建在传统分区或逻辑卷之上

常见

文件系统 描述
ext4 是 ext3 文件系统的升级版。在性能、伸缩性和可靠性方面大幅改进；
支持最大 1EB 文件系统和 16TB 单个文件；
是 CentOS 6.x 的默认文件系统。
Btrfs 2007 年由 Oracle 发布；
因写入性能不稳定、成熟度不足，实用性受限；
Rocky Linux 9.x 虽支持，但官方不推荐生产环境使用。
XFS 高性能日志型文件系统，2000 年左右并入 Linux 内核；
支持最大 18EB 文件系统和 9EB 单个文件；
是 CentOS 7.x 及后续版本（RHEL 7+）的默认文件系统。
swap 用于内存交换的特殊文件系统（非存储数据）；
当物理内存不足时，将部分内存页暂存到磁盘；
建议大小为 RAM 的 1~2 倍（实验环境下要≤2GB）；
是 Linux 启动必需分区。
iso9660 光盘（CD/DVD/Blu-ray）的标准文件系统；
Linux 挂载光盘或 ISO 镜像必须依赖此格式支持；
通常与 udf 或 rockridge 扩展配合使用。

格式化

目的

==写入文件系统==

原理

格式化（mkfs），不是“扫地清垃圾”，而是在这片空地上画图纸、打地基、盖毛坯房。

  • 当你执行 mkfs.ext4 /dev/sda1 时，系统会在这块分区上写下 超级块（Superblock）、索引节点表（inode table） 和 数据块组（Block Groups）。

  • 这就像建立了“户籍系统”：这片区域是存文件内容的（仓库），那片区域是存文件名、权限、大小等信息的（档案室）。

  • 重点：格式化完成后，这块分区里面就已经有了一个完整的文件系统结构，但它与外界（Linux目录树）没有任何关系。它只是一栋建好了、但没装门牌号、也没修通马路的毛坯房。

所以将文件系统挂载到具体的目录上，之所以没有印象，是因为每次开机系统会按照/etc/fstab上的挂载信息自动挂载，只有挂载上，目录树才不算空有其表

分区内部结构

Block

  • 数据块

  • 默认大小4KB，Linux支持1KB，2KB

  • 尽量依次存储

  • 当一个block存储完剩下的空间不再能够使用——block是存储最小单位

INode

  • I节点

  • 大小128B(128 * 8bit)

  • 包含：INode号，相关时间戳，相关权限，数据保存位置

  • INode在分区完成时就已经被规定好了数量，存在被使用完的情况，少见

  • 不要新建写入空文件（空文件虽显示0kb，但已使用inode）

超级块

记录INode总数，使用数，剩余数；Block总数 ，使用数，剩余数···

分区设备文件名（Linux特有步骤）

/dev/hda 1

  • abc代表第几块硬盘，123代表第几个分区
  • hd为IDE接口硬盘——光驱和老式机械硬盘

/dev/sda1、/dev/sdb6

  • sd为SATA 500MB/s，SCSI 200MB/s，USB接口硬盘——主流硬盘和老式SSD固态硬盘
  • ==逻辑分区必须是5后面==
  • 即使主分区+扩展分区!=4：sd1（主分区），sd2（扩展分区），sd3（逻辑分区1）

/dev/nvme0n1p1

  • NVMe（PCIe4.0）7000MB/s
  • 0为存储模块，n1为第一块硬盘，p1为第一个分区
