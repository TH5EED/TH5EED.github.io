Redis集群三种模式

发表于2026-08-16|更新于2026-08-16|中间件
|浏览量:

主从复制模式（Master-Slave）

原理

主节点监听所有客户端请求，负责所有写操作
从节点实时同步主节点的数据
客户端可以从从节点进行读操作，实现读写分离

配置

也可以

优点

  1. 配置简单
  2. 实现数据冗余，提高数据可靠性
  3. 读写分离，提升系统性能

缺点

  1. 主节点故障时，需要手动切换从节点
  2. 主节点负责所有写操作，成为性能瓶颈
  3. 无法数据分片，受单节点内存限制

哨兵模式（Sentinel）

原理

主从复制模式基础上加入哨兵节点，监控主从节点的运行状态
当主节点发生故障，自动在从节点上选举出新的主节点，实现自动故障转移

配置

  1. 主从节点配置不再赘述

  2. 哨兵节点配置

其中，quorum是指触发故障转移所需的最小哨兵节点数。down-after-milliseconds表示主节点被判断为失效的时间。failover-timeout是故障转移超时时间。

  1. 启动

优点

  1. 自动故障转移，提高系统高可用性
  2. 同时还具备主从节点的数据冗余和读写分离

缺点

  1. 配置和管理相对复杂
  2. 依然无法实现数据分片，受单节点内存限制

Cluster模式/分片集群

原理

通过数据分片和分布式存储实现了负载均衡和高可用性

优点

  1. 突破了单节点的内存限制，可更大规模存储
  2. 负载均衡
  3. 自动故障转移

缺点

  1. 配置复杂
  2. 复杂多键操作可能受到限制
