镜像 · 仓库 · 加速站点 全景梳理

核心概念三件套

先区分三个最容易被混用的词：

概念 是什么 类比
镜像（Image） 打包好的应用 + 运行环境，分层存储的压缩包 你下载的安装包 .exe / .dmg
仓库（Registry） 存放和分发镜像的服务器，镜像的”源站” 软件官网的下载服务器
加速站点 / Mirror Registry 在国内的缓存代理，帮你中转 CDN 节点 / 镜像站

==关键认知：Mirror 不是独立仓库，它是上游 Registry 的代理缓存。== 你配了阿里云加速器之后 docker pull nginx，实际路径是 你的机器 → 阿里云 Mirror → Docker Hub，Mirror 有缓存就直接返回，没有再回源。

两大源站：registry.k8s.io 和 docker.io 是完全独立的两套系统

==这是最核心的分辨——两个源站互不相通，各需要各的镜像站。==

源站（Registry） 存放内容 举例
registry.k8s.io K8s 官方组件（apiserver、scheduler、coredns、pause、etcd 等） registry.k8s.io/kube-apiserver:v1.32.13
docker.io（即 Docker Hub） 通用镜像（Nginx、Redis、MySQL、你的业务应用） docker.io/nginx:latest

K8s 组件镜像不可能从 docker.io 拉到，Nginx 也不可能从 registry.k8s.io 拉到。两个域名背后是两套完全不同的服务器。

三类镜像站 / 加速站（按上游源站分类）

第一类：docker.io（Docker Hub）的镜像加速站

这一类数量最多，所有国内云厂商和社区都在做。本质都是 ==Docker Hub 的 pull-through 代理缓存==。

镜像站 地址 类型 备注
阿里云加速器 https://<你的ID>.mirror.aliyuncs.com 云厂商 需登录阿里云控制台获取专属地址，有免费额度
DaoCloud https://docker.m.daocloud.io 社区/商业 无需注册，直接可用，目前使用最广
渡渡鸟 https://docker.aityp.com/ 社区 新兴社区镜像站，2025 年后活跃
轩辕（免费版） https://docker.xuanyuan.me 社区 免费公开
轩辕（专业版） https://xuanyuan.cloud 社区/商业 需注册登录，更稳定
毫秒镜像 https://docker.1ms.run 社区 较新的社区源
腾讯云 https://mirror.ccs.tencentyun.com 云厂商 腾讯云内部用户优先
Docker Proxy https://dockerproxy.cn 社区 老牌代理
原子开源 https://atomhub.openatom.cn 社区（开放原子基金会） 信创/开源生态

==以上所有地址的共同点：上游都是 docker.io，都是拉 Nginx、Redis 这类通用镜像用的。==

第二类：registry.k8s.io（K8s 官方仓库）的镜像站

这一类较少，因为只有跑 K8s 的人才需要。

镜像站 地址 机制
阿里云 google_containers registry.aliyuncs.com/google_containers 命名空间级同步——阿里云定期把 registry.k8s.io 的镜像同步到这个命名空间下

==注意：registry.aliyuncs.com/google_containers 不是透明的 pull-through 代理。== 它和 DaoCloud 那种”你请求 docker.io/nginx，我帮你代理”不一样。它的使用方式是显式改镜像路径：本来要拉 registry.k8s.io/kube-apiserver:v1.32.13，改成了拉 registry.aliyuncs.com/google_containers/kube-apiserver:v1.32.13。

这也是为什么 kubeadm 专门提供了 --image-repository 参数——它就是做这个路径替换的。

第三类：其他特定仓库的镜像站

源站 用途 国内镜像
quay.io Red Hat / CoreOS 系项目（如 Cilium、Calico） 无官方国内镜像，通常配代理或手动搬运
ghcr.io GitHub Container Registry（如 Helm Chart、GitHub Actions 镜像） 同上，部分项目在阿里云有同步
nvcr.io NVIDIA GPU 镜像（CUDA、Triton 等） 部分高校镜像站有缓存
gcr.io Google Container Registry（已逐步迁移到 registry.k8s.io） 阿里云 google_containers 曾经也覆盖，现基本废弃

Docker 架构（你学 Docker 时用的）

配置位置：/etc/docker/daemon.json

K8s + containerd 架构（你现在用的）

==Docker 不在链路里了。== docker pull 拉下来的镜像和 crictl pull 拉下来的镜像，存储位置不同，互不可见。

containerd 的镜像加速配置机制（你真正需要搞清楚的重点）

cert.d 目录机制（containerd 1.7+ 推荐方式）

containerd 有一个关键配置项叫 config_path，定义在 /etc/containerd/config.toml 里：

当 config_path 被设置后，containerd 每次要访问某个 Registry（比如 docker.io）时，会自动去 <config_path>/<registry-host>/hosts.toml 找配置。

类比：config_path 就像一个”注册表目录”，containerd 按需去里面找对应 Registry 的配置文件。你创建一个 docker.io/hosts.toml，containerd 访问 docker.io 时就会自动读取它。

所以完整的生效链条是：

  1. /etc/containerd/config.toml 里设了 config_path = "/etc/containerd/cert.d"
  2. /etc/containerd/cert.d/docker.io/hosts.toml 存在且内容正确
  3. systemctl restart containerd 使其生效
  4. containerd 之后访问 docker.io 就会走 hosts.toml 里指定的 mirror

==这跟 Docker 的 daemon.json 是完全独立的两个文件、两套机制。==

hosts.toml 示例

/etc/containerd/cert.d/docker.io/hosts.toml：

  • server：==声明谁是上游源站（这行告诉 containerd”正常情况下该连谁”）==
  • [host."..."]：指定要使用的 mirror 地址，capabilities = ["pull", "resolve"] 表示这个 mirror 可以用于拉取和解析

如果有多个 mirror 可以配多个 host 段，containerd 会按顺序尝试。

补充：社区镜像站的稳定性说明

==所有社区镜像站（DaoCloud、渡渡鸟、轩辕等）都不是商业 SLA 保障的服务，随时可能失效或被限流。==

稳定性大致排序（截至 2026-08）：

  • 最稳：阿里云/腾讯云官方加速器（需要注册账号）
  • 较稳：DaoCloud（用户量大，社区维护活跃）
  • 一般：渡渡鸟、轩辕免费版（新兴社区，更新快但偶尔波动）
  • 不稳定：各种个人搭建的代理（随时可能关停）

秋招面试时如果被问到”国内怎么拉镜像”，你可以讲清楚这个链条：

K8s 组件镜像从 registry.k8s.io 拉，国内通过 --image-repository 参数指定阿里云 google_containers 同步源绕过。业务镜像从 docker.io 拉，通过 containerd 的 cert.d 机制配置 DaoCloud 等社区加速站。两类镜像上游源站不同、镜像站也不同、配置方式也不同。

nvcr.io NVIDIA GPU 镜像 部分高校镜像站有缓存
